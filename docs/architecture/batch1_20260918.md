## 训练、bench 与 harness

环境提供独立业务数据库；任务给出用户目标、初始条件和评价依据。模型输出工具调用，harness 执行工具、返还 observation、推进模拟用户并判断终止。轨迹保存消息和动作事实，官方 verifier 对实际状态/动作评分。

训练从 train50 调度完整轨迹。GRPO 构造终局组内优势；GiGPO 加入基于可见状态 anchor 的 step 信号；MT-GTPO 使用显式版本的过程 reward 与终局信号做混合信用分配。adapter 将这些信号对齐 token/span/mask，veRL 完成梯度更新、checkpoint 和向 rollout 同步新权重。benchmark 本身不负责梯度更新。

可靠 reward 依赖任务/DB 隔离、正确工具语义、独立 gold replay 与可回放证据。训练 shaping 不能当作官方成功率；官方通过也不保证全部对话承诺正确。训练内 validation 与独立推理评测必须分开。

Harness 分布在 `envs`、veRL agent loop 补丁和独立 `evaluation/runtime.py`。两种执行器共享工具/提示词/验证器，但仍需对原始终止、预算、可见信息和动作顺序做差分验收，不能仅凭同格式分数宣称等价。详见 [调用关系](layout.md)。

- 最终配置/续训相关复验 **42 passed**；共享接口调用方及会话/遥测等 **114 passed**。上述首轮失败均已覆盖复验。不同批次有重复测试，不将数字相加充当独立测试总数。
- 六种 estimator × DF 的完整 Hydra 配置组合通过：20 step、8×8、LR/KL、每 10 step 保存/评测、selection 每任务 4 次一致。另一次 GiGPO+DF 完整 `--dry-run` 通过真实 train50/selection60、DB hash、模型目录及历史任务调度核验，没有启动服务。

## 使用方式

远程激活既有环境后，CPU 配置预检示例：

```bash
source /root/autodl-fs/tau3-core/activate.sh
cd "$CODE_ROOT"
CUDA_VISIBLE_DEVICES="" python -m tau3_grpo.training.rl.runner \
  --estimator tau_gigpo --dynamic-filter --updates 20 \
  --result-dir results/runs/architecture-preflight/new-dry-run --dry-run
```

`--dry-run` 会写新目录的计划和配置快照，不启动模型服务。不要对已有训练目录随意执行。续训需要显式原 checkpoint 和 SwanLab 身份；paper 系列正式训练仍要求有效配方，开发检查通过不等于已校准。

当前公共 runner 面向既有四张策略卡加一张模拟器卡的 A800 正式 profile，不自动适配其他硬件拓扑。

离线比较：

```bash
CUDA_VISIBLE_DEVICES="" python -m tau3_grpo.evaluation.compare \
  --baseline results/runs/post-rl-selection-20260914/selection/sft \
  --treatment results/runs/post-rl-selection-recovery-20260914/selection/e1 \
  --output-dir results/analysis/new-comparison
```

输出目录必须是新的。返回码 0：已记录协议下完整可比较；1：不完整或不兼容并已输出解释；2：读取、参数或输出错误。新增 console 入口为 `tau3-formal-train` 与 `tau3-compare-evaluations`，也支持以上 `python -m` 方式。

## 后续批次与 GPU 边界

1. 解除当前 profile 对历史 pilot 的继承，拆成稳定的模型/硬件/数据/协议组件；逐项对比最终 Hydra 后再归档旧配置。目前不能直接删除 dated YAML。

3. 补训练/独立评测 harness 差分契约、上游真实 diff 的机器补丁清单，继续迁移 env_info 当前控制职责。现有补丁字符串检测不等于完整行为证明。
4. 新 runner 的真实 GPU 更新、权重同步、保存/恢复与 SwanLab 连续性尚未实测。需要用户批准具体 GPU 预算后才执行；CPU 结果不能替代。

消融按 [计划](ablation_plan_20260918.md) 推进。先证明 reward 和信用分配信号可靠，再检验独立成功率与成本，不自动引入参考仓库的其他算法。
