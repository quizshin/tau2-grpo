# 架构后续批次交付（2026-09-18）

本批在第一批之后继续执行 CPU 范围工作。算法仍为 GRPO、GiGPO、MT-GTPO；没有改成参考仓库的算法或训练框架。当前行为允许继续演进，代码/数据/奖励/协议身份按运行记录，不永久冻结。没有启动 GPU 训练、推理、smoke 或恢复实验。

## 已落地的结构

1. **稳定正式配置。** 新增 11 个职责组件及 6 个正式 profile。协议、模型、硬件、数据、模拟器、MT-GTPO 参数和五种奖励版本分别归属对应目录；活动入口不再穿过 formal/curriculum40/fast pilot/matched50 的日期继承链。14 种 estimator/reward/DF 组合与历史完整 Hydra 和有效环境逐项一致。随后显式增加统一事实观测开关，数值参数及预算不变。日期配置保留作为历史复现输入，不批量移动仍有引用的文件。
2. **共享运行接口。** `training/rl/checkpoints.py` 统一完整恢复文件集合、rank/world size、路径、大小和 latest marker 校验；写入方验证后发布 marker，才轮换旧检查点。正式 resume、完成验证、独立评测都使用它。独立评测 controller 移入 `evaluation/controller.py`，旧 `env_info` 路径是同一实现的转发入口。新 console 为 `tau3-evaluation-controller`。
3. **全算法轨迹事实。** `data/trajectory.py` 定义 `tau3_trajectory_facts_v1`：身份、逐轮原始结束原因、工具请求/执行参数与结果、终局验证、精确 response IDs/mask、发出与保留 token span。缺失 logprob/group UID/trial/seed 明确记空，不重 tokenize、不猜测。logprob 完整性同时检查逐轮后端提供状态与最终长度；观察位置的 0 是明确标注的占位，不能冒充模型概率。trainer 的采样 UID 仍在原 batch/replay 字段中，不能把 worker request ID 当作采样组。新正式 runner 显式开启；旧通用 launch 默认不强行加字段。
4. **保持奖励边界。** MT-GTPO 继续独自消费过程奖励 turn records；GRPO/GiGPO 仅增加事实观测。GiGPO anchor hook 仍执行。vLLM `length/stop/abort` 原因按轮保存，现有归一化 stop 字段及终止策略保持；真实后端传输仍待 GPU 验收。
5. **公开配方接口。** runtime 从 `evaluation/rewards/recipe.py` 读取和校验；analysis 负责拟合/导出并兼容旧 import。新配方 schema v2 把公开 reader 纳入身份。旧 v1 仅接受已登记的迁移前校准 SHA，且奖励、核心算法和基准工具哈希必须逐项一致。迁移前用原代码生成的合成 v1 fixture 保留原字节/身份，通过新 reader 验证，并测试篡改及数值源码漂移拒绝。它是测试材料，不是可用于真实训练的通过校准配方。
6. **每批显式诊断。** veRL adapter 通过 `diagnostics_out` 写本批 `meta_info`；trainer 消费本批 estimator/DF 统计。旧 `last_stats` 只为外部兼容保留，正式路径不再读另一批遗留的统计。事实指标去掉 padding 后统计，token 和缺失结束原因有明确覆盖口径。
7. **新评测来源。** `evaluation/provenance.py` 在模型调用前记录实际 task 定义、初始 DB、真实导入的 benchmark 验证器及 harness 文件哈希。比较器已有严格协议/完整性/身份口径，旧结果缺少的字段不从当前代码补造。模型服务权重身份仍由既有 attestation 独立证明。
8. **维护入口与索引。** `configs/experiments/catalog.yaml` 区分正式、历史与未上线候选；`EXPERIMENTS.md`/`ERRORS.md` 继续作为唯一实验/错误索引。分层测试、显式 lint 债务、vendor runtime 清单和文档已接入。

## 真实 harness 对照覆盖了什么

固定模型和模拟用户回复，分别走 veRL 训练 tool loop/项目 session 与独立评测的真实 tau2 Orchestrator。执行真实的取消预订、写后查询以及计算错误，比较工具响应顺序、error flag、最终数据库、终止原因及官方成功/失败分数。相关用例通过，不调用模型 endpoint。

这只是确定性场景对照：不证明真实生成分布、采样参数、全部上下文和轮数边界相同。训练仍有 assistant/user 轮数与 token 限额，独立评测仍有 Orchestrator step/error 限额；保留它们各自的协议记录。可靠官方 reward 来自独立 replay DB 和原验证器，不保证所有业务文本语义都正确；shaping 不作为独立成功率。
