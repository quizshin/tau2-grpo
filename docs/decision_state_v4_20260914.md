# v4 决策状态更新与弃权机制（2026-09-14）

本轮在 `code` 中实现可选 v4 状态更新器及其训练接线，缺省仍为 v1，未启动训练。**机制测试通过，但自动语义抽取未通过真实覆盖检查，不建议启用 v4 进行正式重训。**

## 本轮实现

`tau3_grpo/algorithms/anchors/decision_state.py` 把整句解析与状态更新分开：`parse_event → DecisionState.apply → assess_messages`。

- 维护操作目标、用户身份声明、待确认完整方案、批准绑定、条件、查询许可及此前的财务承诺。
- 第一版语法覆盖明确的取消请求、单航班改舱、完整退款方案、身份/订单引用、批准、拒绝、暂停、撤回和少数条件。它是有限语法，不是通用语义理解或完整 Airline 流程支持。
- 从已经收到的工具结果检查用户/订单关联、支付方式、原舱位和航班范围；保留读账本及工具事件 hash。
- 方案变更后旧批准失效；插入其他问题、改变退款卡或调用新工具之后不能直接将下一句 yes 沿用为旧方案批准。已说出的旧财务方案保留在 guard 中，不能因新方案出现就擅自认定用户已忘记/接受纠正。
- 用户看到的退款承诺与工具读出的价格分别保存，不能用重新计算出的正确金额覆盖曾向用户报错的金额来强行合并。
- 未识别子句、复杂条件、身份/对象冲突、缺少完整方案、工具失败或已有修改操作等情况弃权；未知历史不会因为后续一个 yes 而被清空。此版只覆盖首次修改前的有限状态，修改后的多阶段流程尚不支持。
- 不改变策略模型收到的完整对话，不向工具执行器提供或绕过权限；这个状态只用于优势比较。

v4 在实际 hook 中要求真实 DB hash、policy，以及满足上述规则的结构化状态。仅支持 structured 模式，暂不支持 similarity/DB-only 组合。通过 `TAU3_GRPO_ANCHOR_VERSION=v4` 显式启用；运行目录仍由版本 sidecar 隔离。

## 弃权不能改变折扣时间

检查旧代码发现 `steps_from_anchor_payload` 跳过 `None`。原协议用它表示工具/用户 observation，这是正常行为；如果新增的 assistant 弃权也使用 None，就会把真实动作从折扣时间中删掉。

因此 v4 使用保留标记 `abstain:v4`：

1. ToolAgentLoop 仍记录这个 assistant span。
2. estimator 将它重建为 `anchor_id=None` 的 StepRecord，保留 step_index。
3. 它不加入任何 step group，步级优势为零；其他动作的终局折扣仍按全部 assistant 步计算。
4. episode 优势与原配置一致，工具/用户 observation 的 None 仍跳过。

例如 `[可比动作, 弃权动作, 可比动作]` 的终局回报应是 `[gamma² R, gamma R, R]`，不能缩成 `[gamma R, R]`。控制测试核验了这一点，也确认两个弃权标记不会互相组成步级组。

另补了 v4 专属的 episode-group uid 限制：即使相同任务/状态在一个 batch 对应不同采样组，也不能跨组比较。v1/v2/v3 的历史分组行为不变。此处没有改变归一化模式、奖励定义或 DF。

## CPU 验证

控制测试覆盖完整状态同义表达、报价/货币/退款卡差异、拒绝/暂停/撤回/条件、旧批准失效、未知条件保留、身份与航班核验、弃权计时及采样组隔离。

与既有锚点、真实重放、launcher、会话隔离、并发和算法检查合跑：**245 passed, 2 warnings**（15.76 秒）。两个 warning 是第三方弃用提示。没有模型前后向或用户模型调用。

两批全部通过真实工具重放。v4 的 396 个位置全部弃权，不能据此声称真实误合并率为零或信用分配改善；它根本没有在这些记录上产生可比较组。

主要原因是自由文本中的身份、目标和完整财务方案没有被有限语法完整解析，非初始状态又保留了未解析历史。这**不表示原 Agent 没有查询身份/订单**，也不表示原始数据缺少这些事实，而是抽取层没有把可见内容转换成完整结构。

单独的任务诊断集为 `airline_458/976/994`，按 `sha256("v4-holdout-42:" + task_id)` 排序选择，排除了已有审阅 fixture 中的任务及首批任务；在读取这些对话内容前记录了 reducer hash。没有依据其结果补规则。它只是一组任务隔离的覆盖检查，不是独立人工标注的语义准确率测试。

本轮已观察到的一条上下文反例：E2 的 airline_1060 trial 0 向用户报告退款 2331，而 trial 2 报告 272。不能因为最终工具数据或终局成功相同，就把两种不同的已承诺方案合并。此信息用于确认状态表示应保留承诺字段，不用于锚点输入中的未来奖励。

候选训练配置仍需配合 launcher 的 `--experiment e2` 使用；配置文件的目录名不负责选择算法。本轮没有执行该训练命令。

`abstained/v4` 表示弃权数量；`emitted/<version>` 只是输出非弃权锚点的数量，不代表分组语义正确。重放比较时会排除弃权标记，不能把相同标记误统计成重复状态。

## 当前结论与下一步

这次完成了状态更新接口、方案绑定、保守弃权和计时/分组接线。**仍未获得可用于真实 RL 的自动状态抽取器**。全弃权下 v4 只有继承配置中的 episode 优势；它不能提供额外步级信用，直接开卡重训没有理由期待锚点增益。

后续应把真实完整前缀转成逐字段、带证据出处的审阅标注，评估独立抽取层。若引入模型抽取，也必须校验原文证据、未解析条件和弃权，并在新的任务留出集评估；不再通过对当前留出例子追加正则来宣称泛化。现有状态更新器可作为抽取结果的验证和归并后端，但只有通过完整性检查的结果才能进入步级比较。

不修改历史 v1 实验，不将本次结果解释为 GiGPO 论文无效；5090 配置仍保留在原独立分支，本轮未涉及硬件配置。
