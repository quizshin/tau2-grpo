# 保留轮级优势的调用残差候选：CPU 诊断

后续进展：已接入独立 `call_residual_v1` 并完成真实 token 回放、历史调用级对照及 CPU 测试；小方差风险仍开放。见 [实现与验证](mt_gtpo_call_residual_implementation_20260922.md)。下文保留初次公式诊断时点的状态。

2026-09-22。研究假设：保留原 MT-GTPO 的轮级优势 A_turn，仅用同轮调用奖励差异区分各调用，避免 call_local_v1 替换跨轨迹即时基线后破坏即时/未来贡献抵消。此候选是额外研究改动，不是论文原公式或已证明改进。

```text
q_bar = mean(q_1, ..., q_m)  # 同一条轨迹、同一个 assistant 轮
A_call_j = A_turn + beta * (q_j - q_bar) / (std_original_return + eps)
```

本次只试 beta=1，不做参数搜索。继承原 call_local_v1 的 applied guard（精确归属、组支持、调用同伴支持、非零 return 方差）；只调整奖励不同的多调用轮。无调用、单调用、全同奖励或未通过 guard 的轮保持原值。文本 token 理应沿用 A_turn；本次仅在已有校验后的逐调用数据上诊断，尚未接入逐 token 生产实现。

与现候选差别是取消 `(q-b_call) - (R-mean_R)` 的替换，改成叠加 `q-q_bar`。对符合条件的一轮，调用等权平均优势仍为 A_turn。调用 token 长度不同时，token 加权优势和 PPO 梯度不守恒；不能声称训练更新整体不变。本次 token 加权修正和约为 +5.216805。一般情况下原 return 方差很小时仍可能放大残差，本次不能证明所有数据上稳定。

## 固定数据结果

输入为前次已校验的 128 轨迹、864 调用，文件 `results/analysis/call_local_replay_20260922/calls.json`；计算前将输入 SHA256、公式、固定 beta 和边界写入 `results/analysis/call_residual_probe_20260922/spec.json`。`probe.py` 为诊断脚本，`report.json` 和 `calls.json` 为结果。未改奖励、分组、官方分数、训练代码或旧结果。

519 个有调用轮中仅 9 个轮内奖励不同，6 个通过原 guard，调整 17 次调用（gold_write 8、soft_match 8、state_change 1）。最大绝对修正 0.917349；调用优势最大绝对值为原版/当前候选/本候选 3.404961/4.842506/3.404961。所有单调用与全同奖励轮逐调用原值一致；每轮调用等权平均优势偏差小于 1e-10。

## 能解决与未解决的问题

该公式明确保留单调用及全同奖励轮的旧信用，并按局部奖励大小分配同轮差异。它只保证同轮较高奖励获得相对较高优势，不保证所有正奖励优势为正或所有错误优势为负。

41 次错误中 40 次为单调用，剩余 1 次在本数据上未触发调整，所以错误正优势没有减少。错误调用由后续奖励获得正优势属于时间信用问题，不能靠轮内残差解决。此前去未来项对照也损失成功中间轮信号，不能直接把所有未来项置零或按错误标签强行截断后宣称已解决。

建议将此作为下一轮局部信用候选，先在更大固定 buffer 上核对信号保留、混合调用、方差放大和 token 加权效应；时间信用另做显式、独立对照，避免同时更改两个机制。原版 turn_v1 + split-v4 的 30 步探索仍可作为经验基线，但需解决未校准探索入口及明确运行范围。本次没有生产 estimator 改动、新模型评测或 GPU 训练。
