# Airline 工具观察预算修复（2026-09-09）

RL-003 已完成带真实非零优势的 LoRA 更新，并核对 actor 与 vLLM 的全部 LoRA 缓冲区一致。但对轨迹复查发现，veRL 默认 `max_tool_response_length=256` 是字符数，且从中间截断。真实 JSON 中的航班、原始价格和支付字段会被删掉；这不是 SwanLab 预览截断，模型本身收到的工具观察已经截断。

仅在 200 个 AReaL 训练任务的独立内存数据库中回放参考动作：1,503 次工具返回全部无工具错误，1,283 次超过 256 字符；最大 35,912 字符，另有一次 15,561 字符。32,768 仍会截断一条，因此项目默认改为 65,536 字符，覆盖本次审计的全部参考返回。没有使用官方 Tau3 最终任务，也没有改动数据文件、数据库文件或官方评分。

`MAX_TOOL_RESPONSE_CHARS` 通过 `scripts/train/rl/run_base.sh` 传入 veRL 原生参数。总上下文 24,576、response 16,384 token、每轮 1,024 token、15 轮限制保持原值；特别长的对话仍可能触及总 token 预算。65,536 不是无限长度，也不能保证任意模型生成的任意工具请求都不触限。

新增回归从生产启动器解析实际限制，再调用真实 `get_reservation_details`，确认策略收到完整 JSON 和其中的航班、支付 ID。旧测试直接把限制设成 100,000，没有覆盖生产的 256 字符默认值。

RL-003 固定保留 256 的显式覆盖，便于复现旧诊断；RL-004（full）和 RL-005（LoRA）使用新的 65,536 字符预算与相同 SFT 起点、种子、三步任务顺序及 4B 模拟器。RL-004/006 的 full 首批显存不足，后续由 RL-007 的分块概率计算与 RL-008 的持久盘断点续跑完成链路验证。最终对照应使用 RL-005 和 RL-007 step1 + RL-008 step2/3，并披露恢复及额外采样；见[验证对照记录](rl_validation_comparison_20260909.md)。旧 RL-003 与新 full 不能被当作只改变训练方法的对照。

另外，RL-003 中部分官方 reward=1 的回复仍陈述了错误退款金额；对应任务的 communicate_info 为空，DB 状态正确即可通过。保留官方评分，并把文字质量问题单独记录，不能把 reward=1 解读为回答所有细节都正确。

审计原始报告：`code/results/validation/rl003_boundaryfix_20260909/tool-response-audit.json`；每个工具动作均作用于独立的模拟数据库，不访问真实业务服务。
