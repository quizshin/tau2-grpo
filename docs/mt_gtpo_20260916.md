# MT-GTPO 本地新增（2026-09-16）

后续状态：已合入远程统一主仓库，与 GiGPO 工程修复共同通过 379 项远程 CPU 回归。下述“本地新增”保留原实现阶段记录；合并范围及 GPU 验证边界见 [基线合并记录](gigpo_gtpo_merge_20260916.md)。

本次实现独立的 `mt_gtpo` estimator，复用现有 veRL 更新、用户模拟器与官方终局评分。
不使用 LLM judge、奖励模型或语义状态抽取。原 `grpo`、`tau_gigpo` 与 E0–E3 配置保留。
本次仅本地开发和 CPU 验证，没有同步远程、启动 GPU 训练或完成收益验证。

## 数学约定

第 i 条轨迹包含 K_i 个 assistant generation，k 从 0 开始：

```
G[i,K_i] = official_outcome[i]
G[i,k] = turn_reward[i,k] + gamma * G[i,k+1]
A[i,k] = GN_(uid,k)(G[i,k]) + lambda_outcome * GN_uid(official_outcome[i])
```

默认 gamma=0.9、lambda_outcome=0.3、eps=1e-6。
GN 使用总体标准差（ddof=0）；单例与零方差项为零。晚结束轨迹的末轮不与不存在的轮次比较。
终局奖励位于虚拟 K 位置，因此最后一个 assistant turn 的终局项仍折扣一次。
每个 assistant span 严格覆盖生成 token，observation/padding 不获得优势。
零即时奖励不保证零优势；未来过程奖励、终局奖励和长度差异仍可能产生信用信号。

## 模块边界

- `tau3_grpo/algorithms/mt_gtpo.py`：独立 Numpy 算法，不依赖锚点。
- `tau3_grpo/algorithms/mt_gtpo_verl.py`：注册、payload 校验、Torch 适配与逐批重算记录。
- `tau3_grpo/evaluation/process_reward.py`：确定性过程评分，保存分类和匹配证据。
- `tau3_grpo/envs/interaction.py`：官方终局评分后，在释放私有会话前计算过程评分。
- `tau3_grpo/analysis/calibrate_process_rewards.py`：离线重算、类别关联与建议权重。

## 逐轮记录

`tau3_turn_v1` 保存 turn_index、token_span、parsed、truncated 与全部工具调用。
每次调用保存 ID、名称、参数、执行 error、可见 observation 和执行后 DB hash（可用时）。
同轮多工具按原顺序执行并逐个评分；无工具轮仍有 token span。
上下文在解析前耗尽时记录未解析/截断轮，不编造已执行工具。
工具原始完整输出仍由官方 trajectory_json 保存，过程事件 observation 是策略实际收到的文本。

`process_reward_json` 同时进入 extra_fields 和 reward_extra_info，以 JSON 字符串跨 Ray 传递，
避免变长轮数被 Numpy 推断成不规则矩阵。golden actions 仅用于轨迹结束后的评分，不进入策略输入。

## 两种过程奖励模式

|模式|行为|
|---|---|
|audit，默认|计算候选奖励但实际 turn_reward 全为 0，仍使用新的 hybrid 优势公式|
|conservative|仅奖励 ACTION 属于 reward_basis 时成功执行的首次精确参考动作，并惩罚工具执行错误|

候选权重：gold_exact=1、soft_match=0.5、read_only=0、state_change=-0.1、error=-0.1、
duplicate=-0.2、message=0、unknown=0。可通过 `algorithm.process_reward.weights.<tier>` 配置。
候选分类优先判断执行错误、未消费的精确参考动作、重复已消费动作，然后判断软匹配与工具类型。
软匹配、重复和非参考写操作在 conservative v1 中仍只审计，不影响梯度。
普通只读调用为 0；命中必须执行的参考动作时可以是 gold_exact。

每个 gold 出现次数最多获得一次正奖励；执行错误不消费 gold，允许合法重试。
严格比较嵌套类型和列表顺序，只忽略字典键顺序，不自动转换 ID/数字字符串或删除空值。
有 compare_args 时要求这些键都存在并匹配；否则比较完整参数，避免缺字段被误判正确。
ACTION 门控不证明自然语言授权或政策遵循。这是保守工程变体，不声称逐项复现论文全部奖励规则。
不修改 tau2 官方评分器，也不把过程奖励加到对外报告的官方成功率。

## 可选动态过滤

```
algorithm.dynamic_filter.enable=false  # 全部有效轨迹进入更新
algorithm.dynamic_filter.enable=true   # 先计算完整 hybrid，再整组检查有效优势
algorithm.dynamic_filter.metric=advantage
algorithm.dynamic_filter.mode=fixed_rollout
```

过滤开启时，组内任一有效 token 的 |A| 超过 tolerance（默认 1e-12）就保留整组。
全失败/全成功但有过程或长度信号的组不会被终局标签直接删除。零信号组的 response_mask、
advantages、returns 置零；保留 batch 布局和各 rank padding，不补采样，不跨更新攒组。
过滤不降低已经支付的 rollout 成本，也不承诺降低固定 batch 前后向耗时。
整批过滤时沿用 trainer 的跳过 actor 更新路径，完成计算后恢复候选 mask 供指标统计。
过滤会同时移除被过滤 token 的 actor KL 项；关闭过滤时即便奖励优势为零也可能存在 KL 更新。
原 E1/E3 仍使用原来的 terminal reward 过滤规则，不发生隐式改变。
尚未实现 fixed_informative 重采样；新算法要求 KL 保留在 actor loss，不支持混入 reward。

远程后续运行应先按 AGENTS.md 激活既有环境、核对双方工作区和 GPU，不能直接覆盖同步。

```bash
python -m tau3_grpo.launch rl \
  --config configs/train/rl/qwen35_4b_lora_mt_gtpo_conservative_df.yaml \
  --experiment mt_gtpo --dry-run
```

改变开关/奖励/公式后使用新的 RESULTS_DIR，不复用旧实验目录。
默认新结果路径为 `code/results/runs/mt_gtpo/<variant>_smoke_s42`，重跑应显式指定新 run_id。

## 重算与 IRC

每个训练 rollout JSONL 增加 `mt_gtpo_replay_json`，包含采样 uid、组大小、官方 outcome、
完整过程 payload、算法/奖励/过滤配置、过滤前后 mask、episode/turn advantages 和 returns。
padding 不进入最终日志或过滤统计。候选配置同时启用已有 update-batches 调试快照。

```bash
python -m tau3_grpo.analysis.calibrate_process_rewards \
  --input /path/to/run/rollouts/1.jsonl \
  --input /path/to/run/rollouts/2.jsonl \
  --output /path/to/new_irc_report.json
```

每个输入文件必须是完整 update。程序先重算奖励、优势和过滤 mask，不一致直接报错。
不同奖励/算法版本不混合分析。输出按轨迹中类别是否出现计算 point-biserial 关联、
成功/失败类别出现频率、各类优势正负/零的分布，以及 alpha=1 的候选权重。
默认各相关子集至少 20 个样本；结果或类别没有方差时关联为 null，不伪造为 0。
建议不自动写回配置；另需按任务留出的审计集确认，selection/官方最终测试集不得用于校准。
这不是在线自适应 IRC，也不把关联作为因果证明。
