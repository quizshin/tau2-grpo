以下是本次逐条核对原始场景/消息的分析记录，非人工金标；原judge结果保留。

## 评测与训练的具体处理

1. **保留旧协议分数**：Base54.58%、1epoch50.42%、3epoch44.17%是同一旧协议、已曝光selection60的结果。不得按模型失败挑题删除，不产出扣除漂移后的成功率。
2. **先修任务约束**：逐题核对scenario、初始DB、policy、gold及允许的最终状态，优先处理航班时间矛盾、账户持有人与乘客混淆、DOB冲突、允许任意重复订单但gold固定一个等问题。按与模型得分无关的规则记录旧新版本，修复影响所有模型。
3. **约束模拟器**：固定身份、原始目标、条件目标、允许替代、禁止新增的写操作；允许响应澄清，但不把助手未经工具验证的断言直接当事实。记录脚本偏离和助手诱导两条轴，避免混为一个漂移标签。实现后应先做CPU规则检查，再安排获批的新协议推理验证。
4. **正式比较保持同条件**：冻结任务版本、模型名单、user模型/prompt、采样参数、重复数、预算和异常处理；同一新协议同时重测三模型。保持全任务主分数，并分业务、难度、所需工具、任务族报告；工具覆盖按任务必要动作统计，不能只统计模型实际调用过什么。按任务配对给置信区间，另报告用户脚本偏离和基础设施错误，不静默丢样本。
5. **训练侧继续基于证据修正**：原100条缺少reservation-first开场、98条缺少精确task/DB映射的问题依然待补；资料未查就断言支付方式不可用、时间理解和政策判断错误需要定向补充可执行示范。此次审计没有证明增加epoch能解决，不能据此继续扩大训练。新课程按来源/家族分组、隔离曝光、分桶留dev；final50保持封存。

上述是下一轮协议和数据修复的待办，不代表已经改写模拟器、冻结新确认集或启动新GPU评测。
