# selection60 评分修复与下一步（2026-09-26）

## 已实现的评分协议

本轮沿用题面修订v1，不再修改60题。官方/历史reward单独保留，新版是派生开发评测协议，不冒称未改动的AReaL或tau2官方成绩。

1. **确定性结果**：原生工具重放，匹配该题允许的终态集合；数据库、乘客身份/生日/重复记录、付款记录及无关订单不作宽松屏蔽。乘客列表顺序仍按既有合同视为多重集。
2. **执行路径**：基本舱先改航班、减少乘客数、删除已添加行李等已实现静态规则在逐步回放中检查；不能只看最终状态。补偿顺序和转人工检查实际成功工具调用。
3. **必要沟通**：每题预先冻结任务要求，另为每次写操作生成知情确认检查。DeepSeek只输出逐项pass/fail/unknown和原文证据，不使用五维印象分代替成功率。代码验证引用存在、说话人、确认时序、消息与合同哈希。
4. **模拟器范围**：政策合法不等于题目允许新增目标；新增身份/题外要求被标记为模拟器问题，不自动算模型失败。
5. **无法评分**：judge超时、缺字段、虚构证据、unknown或模拟器漂移进入errors，保留原完整轨迹和计划分母，metrics_valid=false。不能丢题、取交集或把异常直接记0。已保存轨迹可用于后续裁决，无需为judge故障重采样GPU对话。
6. **缓存/预算**：沿用累计100元账本、跨进程锁、调用前预算预留及不可自动重试规则。共用缓存基于提示、题目、检查项和可见对话哈希。历史rubric的Budget/call_json兼容接口仍指向同一实现。
