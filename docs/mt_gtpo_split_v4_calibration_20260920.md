## 为什么没有通过

| 检查 | 实测结果 | 判定 |
|---|---|---|
| 历史拟合 state_change | 支持数40；平均即时 proxy 优势 +0.010071；平均 Hybrid -0.732103 | 即时 proxy 与负向预期不一致 |
| 历史留出 state_change | 支持数5，门槛20；proxy +1.298448，Hybrid +0.881079 | 支持不足，且观测方向仍为正 |
| 工程拟合／留出 state_change | 支持数8／7 | 两部分均不足 |
| 历史与工程完整组的 error、gold_write | 支持数及平均 proxy/Hybrid 方向检查通过 | 不代表每个动作均同方向 |
| 工程仅官方已评分的 error | 平均 Hybrid +0.090683 | 仍有错误信用方向风险；不是另行重建采样组后的结果 |

历史拟合／留出的过程奖励—记录终局相关性为 0.576955／0.569037；工程总体为 0.620912，均不是模型成功率。校准模块退出码2表示正常给出拒绝结果，不是程序崩溃。

原采样组始终完整保留；预算截断仍使用历史记录中的回退分数，不宣称这些轨迹已经完成官方失败判定。工程仅已评分切片沿用完整组计算出的优势。没有降低支持门槛、合并分区、删去截断样本重算分组或搜索系数使检查通过。

## 后续边界

继续复现 v4 需要新一轮固定 SFT 的 train50 采样，保持原40／10任务划分，并检查三类非零奖励在两部分的支持数。不能只给历史留出补15条就宣称形成独立新证据，也不能保证补足支持即可解决信用方向问题。尚未启动这项 GPU 采样，须先准备采样入口、实测资源与有界预算。当前正式训练入口仍要求通过的冻结配方。

本轮已经明确：重复拟合同一批旧数据不能消除缺口；也不能把未通过的候选权重当作已通过校准的算法配方。
