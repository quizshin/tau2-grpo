# 最终评测与简历结论的对应方案

本方案扩充此前 40 任务的训练计划：若要同时支持 SFT→RL、联合方案→GRPO、结构化锚点→DB-only 三个数字，需要五个 RL 训练组及 SFT 基线，共六个最终评测模型。这里只明确协议，没有启动训练或执行最终集评测。

## 对照矩阵

|模型|训练方式|核心比较|
|---|---|---|
|SFT|共同的冻结初始化，不做 RL|RL 相对起点的收益|
|E0|GRPO|基础算法|
|E1|GRPO + fixed-rollout 组过滤|E1−E0：过滤实现的影响|
|E2|Tau-GiGPO，结构化锚点|E2−E0：组合信用分配实现的影响|
|E3|Tau-GiGPO + 组过滤|E3−E0：联合方案；E3−E2：GiGPO 中的过滤影响|
|E2 DB-only|E2，仅替换为 DB-only 锚点|E2−DB-only：结构化状态定义的贡献|

DB-only 与 E2 比，不与同时开启过滤的 E3 比。不能把 E2−DB-only 的差值直接称为 E3 的锚点收益；若要声称后者，还需 E3 DB-only 第六个 RL 训练组。现有 arms.yaml 已有 e2_db_hash_only。

五组均使用同一个已核验 SFT 检查点、同一筛查后 40 任务集合、seed42、每批8任务×每任务8次采样、相同任务顺序、上下文与轮数上限、同一模拟器和硬件，以及同一 full/LoRA 方式。每组上限50个外层训练 step=3200条候选轨迹。E0/E3 的10步诊断包含在50步内；未通过则停止修复，不靠继续烧卡获得看似更好的结果。

## 三层结果

1. train40：记录学习曲线、训练成功率和逐类失败，仅诊断，不写成泛化成绩。
2. selection60：在10/25/50步，每任务4次独立完整对话，计算 pass@1/2/4 和 pass^1/2/4。预先固定选模规则为最高 pass@1；完全并列选更早检查点。同一规则适用于所有 RL 组。
3. final50：在读取任何 final 结果之前冻结六个模型的准确路径/内容哈希、选择依据、模拟器、温度、seed列表、工具/环境版本、轮数上限和指标，随后各评50任务×4次=200条。所有模型同一协议，每次对话独立重置 DB 与会话。不根据 final 再换检查点或调整训练池。

用户模拟器与策略模型分离不等于独立评测；独立性还依赖任务隔离、不使用 final 选模、检查点固定和评分器正确。训练 AReaL 与官方任务 ID 不同，也不构成语义无泄漏的充分证据。

如果使用自定义 Qwen3.8-27B INT4 用户模拟器，应标注“τ³ 官方 Airline 任务集，自定义用户模拟器协议”。使用官方任务不等于复现官方完整协议，不能直接与使用不同模拟器/版本的论文或榜单分数横比。若要宣称复现官方协议，必须另外匹配其用户模型、提示词、采样和环境版本。

## 指标解释

每任务采样 n=4，成功 c 次；成功按官方完整成功判定（约 reward=1），不能把任意正奖励算成功。

- pass@1：平均单次成功概率；每任务为 c/4，再对任务平均。
- pass@4：4次中至少一次成功的任务占比，反映重试潜力，不是稳定完成率。
- pass^4：4次全部成功的任务占比，反映重复执行稳定性。
- pass@2、pass^2：使用已有组合估计实现，不需额外采样。

最终主表列 SFT、E0、E1、E2、E3、E2 DB-only 的 pass@1/2/4、pass^4、相对预注册基线的百分点差和95%置信区间。以50个任务为配对 Bootstrap 重采样单元，10000次；不能把200次对话当200个独立任务。严格要求两模型任务列表一致，禁止缺失困难任务后悄悄取交集。

至少预注册三个主要比较：E3−SFT、E3−E0、E2−DB-only，其他比较探索性报告。若同时声称多项统计显著，应处理多重比较；简历可报告实际差值和置信区间，不必夸大成显著结论。一个训练seed的任务bootstrap不衡量训练随机性；有预算时优先为E0/E3增加训练seed复验，否则明确单seed。

## 过滤与效率的证据边界

固定 rollout 模式不会补采更多有效组，也不会退还已经消耗的采样费用。全成功/全失败组在标准GRPO中的相对优势原本就是零；当前 actor 复用 response_mask 计算策略损失、KL和熵，因此过滤结果不能自动解释成“仅去掉无用策略梯度”。须核对损失归一化与正则项的变化，单独记录KL、有效token和更新范数；若声称仅过滤PG的收益，需要额外对照。

记录候选组数、全0/全1/混合组、有效组占比、有效轨迹/token、实际更新数。不能用删掉无效组后重新定义分母的100%有效率证明效率提升。

吞吐至少分开报告：

- 训练端到端候选轨迹/h：候选轨迹数÷包括rollout、奖励、更新、权重同步的训练墙钟时间；是否包括启动/保存必须写清。
- 有效轨迹/h：混合奖励组中的有效轨迹数÷同一墙钟时间。
- rollout、奖励、更新、同步各阶段耗时；固定5张A800下的GPU小时、峰值显存。

8×8固定不变时，step 与轨迹数线性等价，画两种横轴不是两项独立证据。增加成功率对墙钟/GPU小时曲线，才体现资源利用收益。屏蔽loss不自动减少前向/FSDP通信成本，吞吐必须实测。

## 锚点证据

现有实现统计 anchor_coverage 和 usable_step_coverage，不能直接称为非初始锚点覆盖率。补充或离线重算：

- 非初始可用锚点覆盖率 = step_index>0 且所在可比锚点组至少包含两条不同轨迹的assistant决策步数 / 所有step_index>0的assistant决策步数。排除padding，但不只以已经带锚点的步为分母。
- 非初始非零步级优势覆盖率：进一步要求step advantage非零，避免仅有状态重复却没有信用分配信号。
- 按任务报告结构化/DB-only的组大小、覆盖率与具体错误合并案例。构造时强制无碰撞的哈希指标，不能单独证明语义正确。

## 预算

|项目|对话轨迹数|
|---|---:|
|五组RL，各3200|16000|
|五组各三次selection，每次60×4|3600|
|共同SFT的selection基线|240|
|六个冻结模型final，每个50×4|1200|
|合计|21040|

其中16000条用于RL采样；其余5040条仅评测、不回传梯度。预算不含重试故障、多训练seed及额外官方协议复现。与此前只评最终胜出者的方案相比，这个开销换来能够支撑简历中三种比较的证据。
