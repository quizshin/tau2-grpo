# split v4 错误轮信用分配诊断

2026-09-20。状态 `diagnostic_only`。只在015既有环境隐藏CUDA进行CPU分析，未改生产代码、奖励、优势公式、权重或任务调度；未拟合、采样、推理、冻结或训练。

## 结论

错误轮正优势包含至少三种不同现象：真实工具纠错后最终官方成功、取得局部参考进展但预算结束未评分、以及没有后续参考写入却因同组其他轨迹更差而得到正贡献。第三种不能解释为恢复成功。单纯补数据不能消除该公式行为，但本分析也不能证明它必然降低训练效果。

本轮固定上一轮split v4候选权重及gamma=0.9/lambda=0.3，用原批次、原UID、原轮次分组。只分析历史1,280条与工程256条；它们均为旧reference_write_v3策略产生的轨迹，v4是反事实评分，不是v4训练后的表现。

## 错误后的终局分层

以下“错误轮”指至少包含一个执行错误工具调用的assistant轮次，不是单个调用；同一轮多个动作共享优势。

|数据|有错误的轨迹|错误轮/错误调用|正优势错误轮|其中最终官方成功|其中官方失败|其中预算截断未评分|
|---|---:|---:|---:|---:|---:|---:|
|历史1,280条|408|1,368 / 1,396|379|63|86|230|
|工程256条|100|446 / 450|136|33|23|80|

历史有错误轨迹的结局：57成功、166官方失败、185预算终止；工程对应16、24、60。正优势错误轮对应的轨迹数分别179、54，一条轨迹可含多轮错误，不能将轮次数当成独立样本量。

历史正优势错误轮另有13轮混合同轮正奖励调用，其中12轮的整轮即时奖励非负；工程正优势错误轮无此情况。单个错误调用的负奖励与整轮奖励、整轮优势应区分。

这些错误后成功只能说明整条轨迹恢复到官方成功，不能证明错误本身有益或用户授权合规。后续同名工具成功也是代理指标，未要求它操作同一实体，因此不能单独当作语义恢复证据。

## 正优势主要来自哪里

按照原完整回报的同一标准差，将优势精确拆为：当前过程奖励贡献 + 未来过程贡献 + 折扣终局贡献 + 额外终局优势。最大重构误差2.66e-15；错误轮总体平均优势和正轮数与上一轮独立汇总相符。

|正优势错误轮子集|轮数|即时贡献均值|未来过程均值|折扣终局均值|额外终局均值|最终优势均值|
|---|---:|---:|---:|---:|---:|---:|
|工程：最终成功|33|-0.337406|+0.555360|+0.452149|+0.367912|+1.038016|
|工程：官方失败|23|-0.208809|+1.045929|-0.048976|-0.045372|+0.742772|
|工程：预算截断|80|-0.211322|+0.963670|0|-0.004330|+0.748018|

固定原归一化分母，减掉未来过程这一加法项后，历史321/379和工程109/136个正优势错误轮不再为正。工程官方失败23轮、预算截断80轮全部属于这一情况。该计算只是加法归因，不是删除未来奖励后重新归一化的算法消融，也不是因果效应。

**未来过程贡献为正，不等于自身获得了正的未来过程回报。** 它由“自身未来折扣过程回报−同UID同轮次均值”决定。历史164/379、工程68/136个正优势错误轮，其自身未来过程回报≤0，却因高于组均值获得正未来贡献。

工程23个官方失败正优势错误轮全部满足上述现象，而且后续没有gold_write；其中13轮后面还有工具错误，2轮后面重复了完全相同参数的同工具错误，4轮之后没有任何工具调用。历史86个官方失败正优势错误轮中，77轮属于自身未来回报≤0但相对贡献为正，只有6轮后面出现gold_write。

预算终止的情况不同：工程80个正优势错误轮中61轮后面出现gold_write，历史230轮中195轮出现，存在局部参考进展但最终未获官方评分。不能把预算回退0直接当作已评分失败，也不能仅凭gold_write认为任务已完成。

## 任务、轮次和原采样组

历史正优势错误轮379个中274个出现在assistant第6–10轮；工程136个中104个在第6–10轮。工程121/137次正优势错误调用来自book_reservation；历史335/380次也是该工具，错误信号集中在复杂订票调用。

工程正优势错误轮最多的任务为airline_493（32）、296（28）、574（25）、658（21）、871（17）。这些是已查看的训练任务，不代表新任务泛化。

历史有错误的107个原采样组中62组含正优势错误轮，其中33组没有任何官方成功轨迹，贡献287个正优势错误轮。工程17组中16组含正优势错误轮，其中8组没有官方成功，贡献96轮。“没有成功”包括官方失败及未评分轨迹，不能称为全组已评分失败。

原组始终8条轨迹；同一轮的有效比较成员可能少于8，因为已结束轨迹不参与缺失轮次统计。报告保留每轮group_size和return_std，没有用删掉截断轨迹后的新组计算优势。

## 调用记录复核

按预设类别中优势最大的工程案例选取，属于解释机制的极端案例，不估计总体发生率；完整source/row/turn在examples.json中，以下轮次为代码0-based。

- airline_574、DF on step1、row39、turn10：book_reservation缺少Payment.payment_id和amount，执行失败，后续无工具调用，最终官方0。自身未来回报0，同轮组均值-0.347574；即时贡献-0.213650、未来贡献+1.472606，优势+1.258957。没有恢复证据。
- airline_493、DF off step2、row44、turn7：Passenger缺dob，下一轮继续相同参数错误，之后转人工，最终官方0。自身未来回报-0.317690，组均值-0.895833，优势仍+1.251114。这是“相对少负”的实例，不是错误惩罚漏算。
- airline_574、DF off step1、row9、turn8：订票支付1277与总价1220不一致，下一轮订票成功，最终官方1。说明确实存在工具纠错成功的轨迹，不能把所有含错轨迹都丢弃。
- airline_871、DF off step1、row40、turn8：支付参数缺payment_id，下一轮订票成功，后续还有行李更新，但最终预算结束未评分。可确认局部工具恢复，不能认证最终任务完成。

## 下一步设计建议

1. **先做独立的信用分配消融设计。** 将原Hybrid保留为对照，研究局部工具错误信号与长程任务信用的独立组合。分别检查错误轮、其后的纠正轮和参考写入轮，避免通过压制整个失败轨迹丢掉局部学习信号。独立标准化会改变优势尺度，必须控制尺度并重新验证；本轮没有实现新公式或挑选新系数。
2. **先在已知切片离线验证，再申请新采样。** 重点固定“官方失败且无后续gold_write”“同参数重复错误”“错误后纠正成功”“局部进展但预算终止”四类切片，检查新公式是否削弱无效错误、同时保留纠正动作信号。不能只以减少正错误轮数量作为验收，也不能强制裁剪后宣称问题解决。
3. **补全训练任务覆盖仍必要。** 新校准应固定SFT、覆盖train50，分别达到拟合/留出支持数。它解决代表性和支持不足，不能替代公式消融。此次未制定已授权GPU预算或执行采样。

相对优势本来就在奖励“比组内其他样本好”，少犯错误也可能有用；本报告识别的是局部动作信用解释的局限和可复现风险，而非数学实现错误。实际策略梯度还受PPO比率、裁剪、token权重及KL影响，正优势不等于已证明该错误概率在训练后上升。
