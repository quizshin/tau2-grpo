## 建议范围

维持 Qwen3.5-4B、50 个课程任务、每步 8×8 条轨迹、每组 20 step。完成已有 E0–E3 队列后补推理评测，不为填满简历而默认追加 9B、DB-only、50-step 或多随机种子训练。算法效果不预设方向，最终按实测填写。

每组 1,280 条训练轨迹，四组共 5,120 条；每组 step10/20 各有 selection60×4 评测，四组合计 1,920 条训练期评测轨迹。同一步数和同采样预算在本轮是同一套对照，不能写成两套独立实验。

## 可直接使用的当前简历稿

**Agentic-GiGPO：长程多工具 Agent 强化学习训练系统**　2026.07–2026.09  
个人项目｜基于 AReaL τ²-style 合成任务，面向 τ³-bench Airline 构建 SFT、GRPO/Tau-GiGPO 训练与独立评测框架。

- **多轮训练系统：**打通 Qwen3.5-4B 非 thinking 策略的 SFT→RL 流程，基于 veRL/vLLM 和 5×A800 实现 4 卡 FSDP 策略更新与独立 27B 用户模拟器；适配 14 个工具接口、同轮多调用顺序执行、终局奖励与训练后权重同步。
- **并发与训练稳定性：**通过轨迹级数据库和会话隔离避免环境状态串扰；实现零损失 padding 与保留计算图的空掩码损失，处理无效样本导致的空均值与分布式同步问题；支持整十步完整检查点、SwanLab 连续记录及同一 run 的续训步数校验。
- **组过滤与信用分配：**实现固定 rollout 预算的等回报组过滤，不补采样并统计有效组/轨迹；融合 DB 哈希、工具读取记录、确认及前置条件启发式特征构建结构化锚点，实现轨迹级与锚点组内步级优势组合，提供 DB-only 消融配置。
- **数据与评测：**冻结 1,148 条 Airline 合成任务的 200/60/888 训练、选模与储备划分，从训练池构建 50 任务课程；设计 GRPO、GRPO+DF、Tau-GiGPO、Tau-GiGPO+DF 四组等预算对照，建立独立评测、pass@k、任务级配对 Bootstrap 及官方 final50 的 winner lock。
- **阶段结果：**相同 SFT 起点、20 step/1,280 条采样预算下，GRPO+DF 的训练期 selection60×4 成功率为 52.5%，GRPO 为 47.5%，观察到 +5.0 个百分点；DF 累计保留 760/1,280 条有效轨迹，屏蔽 40.6% 的等回报组样本。

当前 E0/E1 已完成，E2/E3 尚未全部完成；上述“设计四组”不表示四组结果已经齐全。最终投递时用完整结果更新最后一条，删除“阶段”措辞需有对应完成证据。

2026-09-13 的 step20 记录：E0 114/240，E1 126/240。两组各含相同 60 任务、每任务 4 次；将每任务 4 次结果先平均，再对 60 个配对任务有放回重采样 10,000 次，Python random.Random(42)、percentile 95% 区间为 −2.5 至 +12.5 个百分点。它描述当前样本差异，不能证明跨训练 seed 的稳定收益。

训练期评测将达到轮数上限的轨迹记零；E0 有 19 条、E1 有 15 条该类记录，scored=false，verifier 备注为 max_steps 提前终止。独立评测须按其冻结的完成性/异常规则另行汇总，不将训练期输出直接伪装成独立评测产物。

DF 是 response mask 过滤：被屏蔽部分的策略损失、同掩码下的 KL/entropy 也受影响；仍保留前向/反向同步。因此不能把 E1 的收益解释为“物理删去无效序列带来的计算节省”。当前 GRPO 与 Tau-GiGPO 的轨迹优势归一化也有差异，本轮比较的是完整算法配置，不是只打开一个步级项的因果消融。

## RL 完成后的推荐 GPU 工作

### A. 必做：统一服务配置的独立 selection 评测

- 模型：new-off SFT + E0/E1/E2/E3 的 step20，共 5 个。
- 任务：固定 selection60，每任务 4 次，合计 1,200 条。相同任务、seed 计划、温度、上下文/轮数上限、多调用和非 thinking 协议；所有模型采用同一推理精度。
- 现有训练期 step10/20 结果保留，不重跑 step10。只有证明旧 SFT 评测的精确 checkpoint 和完整配置一致才复用，否则补做 SFT。
- 每个模型保存 run.json、完整轨迹、errors.jsonl、summary.json、checkpoint 哈希及服务 attestation；校验计划任务与试验数完全一致后才比较。
- 基础拓扑为 1 卡策略 + 1 卡模拟器；利用现有租用的 5 卡时，先验证 4 个独立策略端点共享 1 个模拟器。全局限流防止模拟器请求超时，不承诺四倍加速。
- 五模型轮流占用策略槽位。先用独立的小规模 smoke 验证吞吐与隔离，smoke 不混入正式结果；固定正式并发与输出计划后再启动全量评测。
- 根据 selection 指标和事先冻结的平局规则选定赢家。不能因为 E3 是联合方案就默认它胜出。

这一阶段结束后，简历已可表述“4B、5 卡、20-step 四组对照与独立 selection 结果”，无需新增 RL。

### B. 推荐：保留官方 SFT→RL 结果时补做最终评测

- 要报告官方数据上的 SFT→RL 差值，必须评测固定 SFT 对照与冻结 RL 赢家；各 final50×4，共 400 条。模拟器和推理协议完全一致。
- 当前 tau3-final guard 仅允许一个精确 winner checkpoint。需要在访问 final 结果前实现并冻结“winner + 唯一 SFT baseline”清单；逐个核验 checkpoint 哈希、角色与固定评测参数。baseline 无资格参与选模，不能用反复改 winner lock 的方式逐组尝试。
- 这是待实现的评测调度/证据校验工作，不是要重新训练模型。若暂不扩展该入口，可仅评赢家，但简历只能写赢家官方分数，不能写官方 SFT→RL 提升。
- 四组差值仍注明来自 selection。如果要写“官方联合方案较 GRPO”，还需事前冻结并增加 E0/E3 官方对照，当前最小方案不默认加入。
- 官方任务集结果受模拟器、prompt 和生成协议影响，保存这些配置；不把本机自定义协议的结果直接声称为官方排行榜同设置结果。

推荐 A+B 共 1,600 条新推理轨迹，不计 smoke；旧结果是否能复用以配置核验为准。E3 后暂预留约 3–5 小时，仅作资源预算，需按独立服务实测吞吐修正。现有训练内 240 条评测用时约 22–23 分钟，不能直接外推独立服务和共享端点速度。

### C. 暂不追加的训练

- DB-only：若以后需要“结构化锚点提升 xx”这一条，再增加 e2_db_hash_only，独立从相同 SFT 训练 20 step，匹配 E2 的任务顺序/1,280 条采样/全部超参，只变锚点模式；预计额外约 6.5–7.5 小时训练，加独立评测。不能从 E2 step20 接着训替代消融，也不能仅对既有模型改推理参数证明训练收益。
- 不追加 9B、30/50-step、多训练 seed、similarity 消融。后续若有明确研究目标再单独安排。

## 无 GPU 工作与关卡顺序

1. 在剩余训练期间，用 CPU 逐组导出已完成的推理模型，限并发并检查 RAM/磁盘余量，不阻塞训练。
2. E2 完成后即开始规划/传输其 optimizer，和 E3 运行重叠；E3 完成后备份其 optimizer。现有持久化代码保存了模型及其他小恢复资料，但没有保存 optimizer。
3. 两组缺失 optimizer 合计约 62.6 GiB；本地本次检查约 96 GiB 可用，可作为暂存目的地。每个文件复制后校验 SHA256，并保存恢复所需的相对路径和清单。无压缩大小保证，不以压缩一定省空间作为前提。
4. 关卡前核验模型、optimizer、RNG、dataloader、step、代码/依赖/配置及 SwanLab run 身份齐全。备份分布在 FS 与本地时，生成重组说明并逐项对照原完整检查点清单；不能只确认权重已归档。
5. GPU 推理任务全部结束、唯一内存盘资料转出完成后，通知用户可以关 GPU。无需等待报告。不能把关机后会消失的 /dev/shm 资料留待无卡模式读取。
6. 无卡时完成完整性审计、任务级配对 Bootstrap、pass@1/2/4、失败归类、DF 有效组统计、吞吐计算、图表及最终简历替换。

吞吐分别报告训练采样轨迹/rollout 时间、训练轨迹/训练时间和包含启动/保存/评测的端到端时间；不要混用分母。当前聚合 anchors 指标不能改名成非初始覆盖率。配对报告前先验证完整任务集合一致，不能静默取交集来排名。
