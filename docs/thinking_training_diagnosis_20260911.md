# Thinking Agent：当前问题与下一轮实验设计

日期：2026-09-11。依据任务“qwen35测试分析”、当前 code 源码与本地归档数据。本文是诊断和建议，未修改训练代码、训练数据、历史成绩，也未启动 GPU。下面建议的预算是新实验起点，不是论文参数或已经执行的实验。

## 1. 项目应当回答的问题

建议第一阶段只回答：在固定 Airline 环境、工具协议、用户模拟器和推理预算下，Qwen3.5-4B 的 Thinking 版本能否通过经过审核的 SFT 和在线 GRPO，提高未参与训练的任务成功率？

先完成 4B 的受控实验；9B 是后续独立规模实验，不能将 4B 的结果等效写成 9B 成绩。暂不扩展 E1/E2/E3，不等于删除已有实现；先建立可信的 Base → SFT → GRPO 基线。

当前实际口径是 AReaL 合成 τ²-style Airline 数据训练/选模，冻结 τ³ 官方 Airline 50 题做最终跨版本评估。内部 selection 提升不自动等于官方 τ³ 提升，也不是全领域成绩。

历史文档中“正确对话”“语义隔离完成”等概括须按证据理解：当前 reason_similarity 使用词集合 Jaccard 与 SequenceMatcher，是文本近重复筛查，不能独立证明语义等价任务完全隔离。

## 3. 先把协议变成一个可以验证的契约

推荐第一版沿用官方单调用语义：一个 assistant 决策最多一个工具调用，工具结果返回后再决策；统一 SFT、RL、评测使用的政策版本、工具 schema、日期和终止规则。

- 不再静默丢掉第 2 个及后续调用。对不合法输出产生明确、可记录的错误反馈；区分协议失败与环境基础设施失败。
- 对旧示范不能仅替换 system，也不能任意插入工具结果。只有相互独立、具备完整对应结果的读调用才能考虑有证据地顺序化；旧 reasoning 若写“同时查询五笔”，也需修正。写操作、依赖调用或历史变化的轨迹优先重采样并验证。
- 对比源 SFT 政策与目标 runtime 政策。若取消资格、确认要求或业务规则不同，须在目标规则下重验轨迹，不能把旧回答直接换个提示词继续监督。
- 思考保留在训练/策略日志中；用户模拟器接收面向用户的 content，不接收内部 reasoning。工具解析器只能执行真实 action 区域，不能执行思考中提到的工具。
- 计数分别记录助手决策次数、用户往返次数、工具调用数和生成 token 数。将一次多调用拆成多次调用会增加决策数，原 15 轮上限必须重新验证。

## 4. SFT 要教什么、数据从哪里来

SFT 的可检验目标是教会正确的行动方式：读政策与事实 → 判断条件 → 缺信息时询问 → 需要时获得确认 → 执行写工具 → 根据工具结果总结。成功依据来自真实状态与验证器，不来自语言上声称成功。

第一步盘点现有 999 段来源，而非从零生成大库。建议先审核约 100 段候选作为小规模数据试验，再视质量与覆盖扩展到约 300–500 段；不要为了凑数放宽质量要求。最终规模由审核通过量与学习曲线决定。

候选接纳要求：

1. 保留 source revision、dialogue/task ID、原始 correct/reward、DB 标识、政策版本与工具 schema hash。旧数据找不到可重放 DB 时，标记为“内容审核通过、未执行重验”，不能叫环境验证成功。
2. 核对当前信息边界：thinking 只使用当时用户/工具已提供的信息，不能使用后续反馈、隐藏用户目标或 evaluation_criteria。已有 reasoning 不等于高质量。
3. 校验工具参数、调用和结果配对、执行前置条件、金额/日期、终止原因；由确定性检查和独立内容审核共同判断。合理拒绝、转人工不能一律当作失败。
4. 对可重放来源，在对应初始 DB 上执行并使用固定验证器；修改上下文/调用顺序后必须重新验证。
5. 按源对话、任务家族、DB/目标状态关联分组再切分，不能把同一对话不同 turn 分到 train/dev。不能仅靠改 ID/姓名制造独立样本；也不必将所有“改签”任务粗暴视为同一任务而全部排除。

覆盖表至少包含：取消/改签/订票/乘客/行李；允许与不允许操作的边界；缺信息与确认；两项以上组合目标；工具失败与恢复。每格记录独立任务数、成功/拒绝示范数及平均长度，再决定补什么数据。

现有池不足时，从已隔离的训练任务及其 DB、用户情景和验证器重新采样：教师仅看 policy 和可见历史，用户模拟器只看自己的情景，环境真实执行工具，验证器在轨迹结束后检查结果。每题可以先取 2–4 个候选，优先保留通过检查且策略不同的成功轨迹。不要事后给错误动作补一段听起来合理的思考。

### Thinking 的监督实现

需要同时保证字段进入原生模板与 reasoning token 被标记为训练目标；只把 enable_thinking 改成 True 不足以证明做到这一点。当前 mask 适配主要围绕 content、tool_calls、EOS，必须重新检查思考区间与历史思考处理方式。

第一版可用“每个 assistant 决策一条监督样本”：输入为截至当前决策的合法历史，target 为这一轮真实的 reasoning + content/action，只有 target 计算交叉熵。完整对话仍是切分单位。原生模板若会去除旧回合的 reasoning，不要误称全部历史思考都参与监督；历史是否保留应和部署行为一致。

完成十条人工检查：实际渲染文本、token 与 label 对照，思考/action 的 label 非 -100；system/user/tool observation 的 label 为 -100；无未来信息；推理/工具格式能在在线交互中闭合。

建议新 SFT 从原始 Qwen3.5-4B checkpoint 开始，旧 non-thinking SFT 保留为历史对照。初始可继续 r16/alpha32、有效 batch 8，LR 2e-5、1–2 epochs 作为保守试验；这些值尚未验证最优。逐决策样本与完整轨迹的 batch 含义不同，要按监督 token 和完整对话贡献记录预算，避免长对话被无意过度加权。上下文长度根据开启思考后的实际分布定，不沿用旧 16K 合格结论。

## 5. RL 要优化什么、训练数据是什么

RL 数据不是另一份成功对话答案库。每个样本需要 task ID、初始 DB、用户目标与约束、policy/tools 版本、目标状态/验证逻辑和来源 hash。Policy 只看允许的对话与工具信息，隐藏用户目标由模拟器使用，验证器答案不进 prompt。

先使用现有 200 个 train task，逐项检查可执行性及语义迁移，不立即扩展 reserve。建议在其中约 32 个覆盖不同类型的任务上先各采 4 条，估计当前 Thinking checkpoint 的成功率与有效组比例；这是有噪声的训练诊断，不用来报告泛化成绩。

对纯 outcome-GRPO，每题一组轨迹：全 0 和全 1 均没有组内结果差异。全 0 时先区分任务/验证器错误、协议失败、超长与真实能力不足；全 1 时可减少重复预算但仍报告。不要用复杂奖励掩盖数据或执行错误，也不要为了产生梯度直接更改官方成功标准。

初始只跑 E0 GRPO，参考起点为 LR 1e-6、每题 4 rollouts、每批 4 个任务（显存不足可分批），约 10–20 次更新观察趋势，每 5 次做固定 dev 评估。该预算是试验上限建议，不能保证有效提升；验证了有效信号与 dev 趋势后才扩大训练。保留官方奖励定义，过程错误先作为诊断项，后续如做奖励塑形需单独消融。

Thinking 产生的 token 与 action token 一起参与策略 loss，用户/工具输出排除；检查采样 token、旧策略 log-prob、loss mask 与推理权重同步。原单轮 1,024 token 和 15 轮可能造成新模式截断，先用小样本测分布，再冻结预算。4B 旧 RL 的策略卡峰值约 77.9GiB/80GiB，不能据此承诺开启思考后原配置仍可运行。

## 6. 最小实验顺序及判断依据

| 顺序 | 实验/产物 | 要回答的问题 |
|---|---|---|
| 0 | 协议与模板验收、来源审计 | 输出是否都被执行？思考是否确实被训练？ |
| 1 | 原始 4B Thinking 在固定 dev 上评估；可加原始 non-thinking 对照 | 不训练时的成功率、预算和失败类型是什么？ |
| 2 | 清洁 Thinking SFT，同一 dev | 相对原始 Thinking，能否减少具体失败并提高成功率？ |
| 3 | 原始 Thinking 直接 GRPO 与 SFT→GRPO 二选一或小规模对照 | SFT 是否必要？在线奖励能否带来额外收益？ |
| 4 | 增加任务和预算，保留最好 dev checkpoint | 结果能否在更多任务与随机种子下保持？ |
| 5 | 冻结方法/模型/推理配置后统一官方评测 | τ²-style 内部收益能否迁移到 τ³ Airline？ |

数据质量小试可在 60 个 selection 中预先固定约 20 题作为 debug 子集，同一模型每题 2 次用于快速定位；这些任务之后仍属于已用过的 dev，不能冒充未见测试。阶段比较用完整 60 题 × 4 次，固定 task/trial seeds、模拟器、policy、温度、token/回合上限与判分器。先同推理预算比较各 Thinking checkpoint；若比較 thinking on/off，还应同时报告成功率与生成成本，额外思考预算带来的收益不能当作纯训练收益。

主指标建议 pass@1，辅助 pass@4 与 pass^4，记录工具协议错误、无写操作却宣称完成、超限、用户模拟器异常、平均 token 和时延。置信区间按任务配对重采样，重复 trial 不作为独立新任务。5 条 SFT validation loss 只用于拟合诊断，不替代任务评估。

若继续当前“官方 50 题只评估锁定赢家”的约定，最终只能报告该模型的官方成绩。若要声称训练令官方成功率提高，应事前约定原始 Thinking、SFT、SFT+RL 三个冻结 checkpoint 的最终比较；按同一协议一次评估后不再据结果调参。现有 winner-lock 入口须相应明确比较模型范围，不能绕过锁定逻辑挑赢家。

## 7. 近期应得到的三个具体交付物

1. 一份覆盖/质量清单：现有 999 段中多少可用、多少有思考、多少可环境重验、哪些任务分支缺示范、每段为何被纳入或排除。
2. 一份已人工核对的 Thinking 数据样例与渲染/label 对照，连同同规则运行的工具轨迹。
3. 一张固定 dev 上的 Base Thinking / Thinking SFT / Thinking SFT+GRPO 对照表，包含成功率、成本和失败类型；无提升也如实记录，再决定数据或算法方向。
