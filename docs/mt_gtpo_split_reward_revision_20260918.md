# MT-GTPO 参考查询／写入奖励拆分修订（2026-09-18）

## 已实现的独立版本

新增 `paper_env_split_v3`，保留 `paper_v1`、`paper_env_v2` 和 reference_write v1/v2/v3 的既有含义。
这是本项目的奖励适配变体，不是作者算法原样复现。先前已查看 selection 并据此发现问题，所以本次结果只能标记为开发验证，不能称作全新的盲测。

执行参数规范化、乘客／航班列表顺序、工具执行错误优先、参考动作一次性消费以及状态变化后重复读取的判定，全部沿用已修复的环境匹配器。
改动发生在精确匹配之后：

- `gold_read`：精确参考查询，包括已有只读工具和 get_flight_status；当前配置即时奖励为 0。
- `gold_write`：精确参考数据库写入；当前配置在训练数据上估计正权重。
- `gold_exact`：保留给转人工等非数据库、非只读的其他精确参考动作；当前配置为 0，不混入 gold_write。
- 其余 error、state_change、soft_match、duplicate 等分类和优先级不变。

即时奖励仍按同轮所有调用求和，不加入新的预算、终局成功门控或优势裁剪。
查询即时奖励为 0 不代表查询的训练优势为 0；未来回报、终局结果和组内相对归一化仍会给查询分配信用。
终局奖励、Hybrid 公式、gamma=0.9、lambda_outcome=0.3 以及动态过滤算法未改变。

取消 gold 固定 +1 锚点策略，仅为 gold_write、error、state_change 拟合权重，其余为显式中性。

使用原有 20 个训练 buffer、1,280 条轨迹。固定40任务／960条拟合、10任务／320条原留出划分。

## 奖励密度与仍存在的限制

| 训练数据指标（1,280条／12,591轮） | 旧保守配方 | 新拆分配方 |
| --- | ---: | ---: |
| 有非零过程奖励的轨迹 | 1,275 | 952（74.38%） |
| 有正过程回合奖励的轨迹 | 1,273 | 697（54.45%） |
| 非零奖励回合 | 4,929（39.15%） | 2,276（18.08%） |
| 正奖励工具调用 | 6,418 | 1,056 |
| 负奖励工具调用 | 1,532 | 1,532 |

即时过程奖励变稀疏了，减少的是高频参考查询的直接正奖励；不能声称稀疏问题已经消失。
终局信号与未来回报的信用传播仍保留。实际训练是否更好需要新模型对照，不能用离线相关性代替。

其他未解决的限制也保留：

- state_change 在原训练留出上的出现性相关系数仍为+0.118562，与拟合集相反；当前验收检查平均优势方向，不保证类别在每个任务上都应受罚。
- 负奖励不保证每次错误调用的最终优势为负。step10／20仍分别有28／7次error调用得到正Hybrid优势；未裁剪或掩盖这些结果。
- soft_match包括部分错误写入等异质行为，目前仍中性；本次只拆精确参考匹配，未声称解决所有不良激励。
- 参考数据库写入只代表与给定参考一致，不证明用户授权、策略合规或唯一合法解。
- 新配方结构受到已查看selection诊断启发；所有当前selection结果均属于开发证据，不是未接触的最终泛化测试。
