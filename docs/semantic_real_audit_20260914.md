# 真实轨迹语义审计与接口选型

这次只做 CPU 重放与真实 API 抽取，没有启动 GPU 或 RL。当前证据不足以将外部
语义抽取接入正式 GiGPO 训练；模型返回快与能稳定生成可靠状态是两个指标。

## 数据与冻结方式

来源为本地 non-thinking SFT 的 selection 评测，共 239 条轨迹、60 个任务。
这是模型与环境交互产生的真实轨迹，不是手写样例，也不是原始 RL rollout 分组。
原 E3 分析目录当前不可用，不能用本次结果冒充 E3 训练覆盖率。

排除此前审查过的任务后，按 `sha256(semantic-real-v2-42:task_id)` 排序选取前三个，
读取对话/奖励前锁定：airline_683 用于模型选型；airline_706、airline_378 用于审计。
每个任务四次试验，固定抽取动作发生前的 assistant step 1/3/6。
12/12 条轨迹通过工具响应重放验证，共 84 个工具响应、129 个认证决策位置。
这不表示恢复了用户模拟器的隐藏状态。

正式审计 24 个位置，18 个不同前缀；相同前缀共用一次抽取。API 只收到可见历史，
不收到任务答案、终局奖励、当前待生成动作、未来消息或配对标签。奖励另存，
仅在冻结标签、启动抽取后读取，用于事后信用信号诊断。

22 对标签由 Codex 审阅，非独立人工标注，也不是大规模语义准确率基准：

- 12 对相同初始前缀，仅检验缓存一致性。
- 3 对真正同义的中间状态，应合并。
- 3 对工具知识不同的中间状态，应分开。
- 4 对 DB 相同但报价/确认范围不同的状态，应分开。

完整锁定清单与标签见同目录 `semantic_real_audit_lock_20260914.json` 和
`semantic_real_audit_review_labels_20260914.json`。本轮没有根据审计结果修改冻结的
v2 prompt、状态归并或证据规则。

## 模型速度实测

同一网关 `https://llmapi.paratera.com/v1`；单请求总时限 180 秒，无自动重试。
首轮相同两个前缀、temperature=0、max_tokens=8192；下面为单次测量，非稳定吞吐基准。
长前缀约 12,419 个 JSON 字符。秒数是接口请求耗时，不包含全部本地处理。

| 模型 | 短前缀秒 | 长前缀秒 | 通过协议/证据校验 |
|---|---:|---:|---:|
| Kimi-K3 | 169.2 | 180.0，总时限 | 1/2 |
| GLM-5.3-Flash | 34.2 | 88.0，未正常结束 | 1/2 |
| Qwen3.8-Flash | 24.4 | 180.0，总时限 | 1/2 |
| DeepSeek-V3.2-Instruct | 13.2 | 98.1 | 0/2，乘客范围字段不合法 |
| GLM-4-Flash（补充） | 17.8 | 84.3 | 0/2，goal/费用字段不合法 |

GLM-5.3-Flash 显式请求 `thinking.type=disabled`：短请求 HTTP 400，长请求约 92 秒
但未正常结束，0/2。不能认为该网关已可靠支持此参数。另将长前缀 max_tokens
升至 16384，约 163.8 秒后仍未正常结束，0/1。
客户端此次未保留失败响应的具体 finish_reason/usage，不能把所有非正常结束
都断言为输出 token 截断，更不能据此推断模型完整的内部推理行为。

暂选 GLM-5.3-Flash / 8192 做有界诊断：短前缀有效且比 Kimi 快，长请求也能在
总时限内返回。它尚未通过长对话选型门槛，所以 `.env` 默认 Kimi-K3 保持原样，
新增配置只覆盖本次诊断模型。没有把“Flash”名称当作性能或准确率保证。

## 冻结审计结果

GLM-5.3-Flash 共 18 次请求、并发上限 4，单请求 49.3–95.9 秒，中位数 84.0 秒。
各请求耗时之和 1426.8 秒不是并发运行的墙钟时间。

| 位置 | 通过协议/证据校验 | 含义 |
|---|---:|---|
| step1 | 8/8 | 两个不同前缀，各复用于四个 trial |
| step3 | 1/8 | 唯一通过的中间状态仍有原文保留项 |
| step6 | 0/8 | 全部无法生成可用状态 |
| 合计 | 9/24 | 去重后仅 3/18 个前缀有效 |

15 次失败均为接口输出未正常结束，被客户端拒绝；不是已证明这 15 个状态语义
不可比较。12 对相同前缀检查通过；10 对真正语义配对全部弃权，0 对可判定。
因此没有可报告的语义配对准确率；零误合并只是没有可用比较，不能称为 100% 安全。
唯一形成的两个多 trial 状态组均为完整的初始四条组，无新的中间状态细分。

117 项相关 CPU 测试通过，Ruff 与 diff 检查通过。测试覆盖输入/结果身份和哈希、
未来信息隔离、弃权不计成功、完整组不算新子组，以及接口模型覆盖和 thinking
参数显式配置。测试通过不等于真实模型抽取通过。

## 真实状态中需要区分什么

airline_378 step6：不同 trial 的数据库相同，但助手承诺退款 2380 与 2504，
不能合并；另两条分别为已批准完整 2462 方案与仅选择退款卡、尚待完整确认。
airline_706 step6：报价 360 与 924 不同；另一条用户质疑 681 的价格、要求解释，
不能当成与批准 924 的状态等价。终局数据库成功并不抹去这些中间承诺差异。

通过校验的一个 step3 仍将整段身份询问保留在 `opaque_context`，且将提供身份信息
表示为一个 lookup 目标。前者会保守地按原文分开，后者是否忠实表达意图还需标注；
事件 JSON 有效不等于已经证明完整语义正确。

## 信用信号与后续门槛

冻结的两个审计任务四次试验均成功，奖励均为 1。在以不折扣终局回报比较的诊断中，
任何子组都没有奖励差异；无法用它们证明新的步级信用信号。这里没有把稀疏抽样的
三个位置误当成完整轨迹去计算 gamma=.95 的训练优势。实际 GiGPO 的折扣与完整
剩余步数可能产生额外差异，本审计不估计那部分。

事后清点原数据，有 59 个完整四次试验任务，其中 22 个成功/失败混合。后续可另建
明确标为“按奖励分层”的诊断集，先固定输入与标签再抽取；不能将它替换进本轮盲选
样本来提高成绩。即使出现可比较子组，也要证明它是原组的有效细分，而非把整个
原组再复制一次，并与相同采样预算 GRPO 做 GPU 对照后才能声称训练收益。

优先改进方向是有证据约束的增量抽取：本地给新消息分配证据片段 ID，模型只报告
本轮事件，代码维护既有目标、报价与确认版本；遇到不支持的内容仍弃权。它有望
减少重复输出整段历史和手算字符偏移的负担，但尚未实施或验证。应在新版本上
重新冻结协议，并用新的留出真实对话检查费用、范围、旧批准失效与同义归并。
