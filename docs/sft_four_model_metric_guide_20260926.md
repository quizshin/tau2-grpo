# 四模型指标说明与新旧分数区别

原生任务成功、严格合规、等价合规、终态分量是不同口径。以下全为同一批240条保存轨迹的读取，不改变评分。

|模型|原生任务结果|严格合规原标通过数|等价合规原标通过数|附加评分未决数|
|---|---:|---:|---:|---:|
|Base|46/60 = 76.67%|22|22|3|
|旧SFT1|36/60 = 60.00%|16|17|5|
|Base→修复SFT|43/60 = 71.67%|20|22|8|
|旧SFT1→修复SFT|35/60 = 58.33%|11|11|6|

后两项是原自动评分标签的已标通过数量，不是完整成功率，也不是全部经独立复核的通过数量。计划分母始终为每组60；不能删未决项，以22/57等形式当作完整成功率。22条异常的诊断裁决另存，尚未覆盖原始结果。

## 各指标究竟检查什么

1. **原生任务结果**：保留simulation.reward_info.reward。本轮奖励依赖DB与communicate检查，而任务没有显式communicate_info，后者自然通过；因此主要反映参考DB匹配及运行终止等条件，不保证逐笔金额披露、确认顺序和全部解释正确。76.67%属于这一项；不是官方原封final50成绩。
2. **严格合规（reference_compliant）**：冻结的规范化参考终态，加正常终止、非DB奖励、政策、必要工具、语言要求及事前确认等共同条件。不是逐工具调用序列一模一样。
3. **等价合规（equivalent_compliant）**：允许事前冻结的其他合法终态，仍须通过同样合规条件；不能把任何总金额相同或任意动作顺序都视为等价。
4. **合法终态诊断分量**：保留预算/正常终止，只检查是否进入冻结合法状态集合，不含完整语言、政策或scope。四组分别48/60、37/60、48/60、39/60；不能冠以完整任务成功率。

例如repair_base/994有原生reward=1，但首次明确说明50费用后、执行前缺少新的明确确认，附加确认检查未通过自动校验。数据库结果正确与所有沟通条件满足可以出现不同结论。

## 为什么Base从54.58%变成76.67%

旧轮131/240=54.58%，包含60题×4seed；其中seed42为30/60。本轮46/60=76.67%，只有seed42。检查点、agent system prompt及原生评分器哈希相同。
但是34/60场景与22/60参考调用变更，模拟器增加scenario_fidelity_v3约束，user temperature从0.7改为0。题目ID和DB相同不足以证明任务相同。旧54.58%同样是原生指标；不能说上涨来自取消合规检查，也不能归因于Base模型提高。
没有逐项控制实验，无法分离题目修复、模拟器及采样次数各自贡献。新四组内部协议一致，能够作本轮开发集的描述性比较；不能据单seed声称稳定泛化提升。

## 后续报告约定

每次并列原生结果、冻结严格/等价合规的完整性及已标通过数；终态分量放诊断列。主指标原冻结为equivalent_compliant，其完整率目前不可用，不能因为原生数高就把原生指标改称事前主指标。能力Rubric用于解释失误，不替代任务指标。
