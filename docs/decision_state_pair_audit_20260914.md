# 决策状态应合并/应分开：无卡审计（2026-09-14）

结论：**现有 v3 暂不值得直接重跑正式 RL；值得继续无卡改进状态抽象。** v1 对用户已表达的具体目标和条件区分不足，v2/v3 又把语义等价的真实长句拆开。本轮只增加诊断样例、审计脚本及文档，没有修改生产锚点、归一化、训练配置或历史成绩，没有启动模型、GPU 训练或 SwanLab run。

## 审阅口径及范围

本轮建立 47 对状态，由 Codex 阅读完整可见前缀逐条给出关系及理由。标签在查看本轮锚点预测前建立，未读取 reward 或后续动作来决定关系；不是用户或外部专家标注，不是随机抽样的独立准确率测试。相同任务/轨迹可参与多对，不能把相关样例当独立观测计算总体置信区间。

- 28 对自然样例：12 对候选应合并、12 对应分开、4 对证据不足，来自 E2 同任务不同 trial 的首次用户发言。两边开场相同，此时尚无工具调用。
- 6 对真实前缀的受控改写：3 对等义改写、3 对意义相反/不同的改写，保留完整既有上下文；改写侧不是另一条真实 rollout。
- 12 对控制样例：3 对应合并，9 对应分开，检查方案范围、条件、撤回、读结果、JSON 格式、工具调用 ID、DB 与 task。
- 1 对预算边界：相同对话、不同剩余轮数。保留为建模上的不确定项，不将现实现未按预算拆组判作错误；原 GiGPO 允许跨时间重复状态。

“应合并”指所定义的**可见决策语义抽象**一致，不证明原始 policy observation、用户模拟器隐藏状态或有限时域价值完全相同。输入按匹配 DB 假设构造：自然样例尚未调用工具，后续真实前缀只含读工具；本轮未重放中间 DB，也未恢复线上训练锚点。

标注数据是开发诊断集，包含上一轮已知的语义规则与反例，不能用其控制样例的高分宣称泛化能力。E3 已有轨迹本轮未用于建立标签，可作为未审阅对话来源；同一任务的另一次 rollout 不是独立任务留出集，后续应按 task_id 去重划分开发与验证任务。

## 是否存在可比较的收益差异

先固定 fixture 和预测结果的 SHA256，再由独立脚本读取自然应合并对的终局奖励；奖励没有进入标签或锚点输入。

12 对自然候选中有 3 对终局奖励不同：airline_1106 的 0/2、2/3，以及 airline_14 的 0/2，涉及 2 个任务；其中两对共享同一失败轨迹，不能视为三份独立证据。

这只说明可以继续研究相似决策语义下的不同后续结果。它不是计算出的训练步优势，不证明当前动作导致成败，也不证明相对于 GRPO 多出了有效信用；早期状态的信号尤其可能与 episode 项重复。

## 对下一版状态表示的约束

不建议通过全局放宽相似度或删除历史来追求重复率。应先选择有限动作范围（例如改航班/行李或取消），建立可检查的语义状态：

1. 同一任务/episode 比较组及 DB；区分用户声称和工具核验的身份、会员与订单信息。
2. 当前完整目标及保护条件：对象、日期/舱位/乘客/行李数量、不能修改的范围、尚未解决的请求。
3. 最新待确认方案：动作参数、金额币种、支付方法、用户是否已看到该版本；方案变化后旧批准不能自动复用。
4. 批准/拒绝/撤回/条件状态与未完成核验；读事实、工具失败及已经发生的副作用。
5. 对完整解析且证明冗余的措辞进行合并；未知子句保留或明确弃权，不通过少数已识别 slot 丢弃其余内容。

是否折叠已失效历史、如何处理用户模拟器的隐藏会话状态和剩余轮数，需要单独验证。将整段历史换成结构化状态是一种有损抽象，不能只凭本轮样例就宣称是完整 Markov 状态。

## 重训判断

**当前不建议正式重训 v3。** 本轮已经暴露可重复的漏合并，即使控制反例全部通过，也不足以证明真实对话可用。

下一次值得开卡检查的前提：先让有限领域状态抽象处理这些开发案例，再对未参与开发的任务/对话进行独立审阅；同时检查合并的正确性、弃权比例，以及真实中间决策的匹配机会。之后才做 1–2 step 小检查，核对实际 DB 下的非零步优势、相对于 episode 项的差异和 DF 屏蔽量。

本轮诊断不否定 GiGPO 方法，也不能把旧 E2/E3 未超过 E0 的原因全部归于锚点。
