# 真实对话字段抽取与证据校验（2026-09-14）

本轮完成 **CPU 离线证据层**：从复合句、Markdown 表格和工具返回中定位真实字段，提供可复查的状态审阅视图。它解决 v4 把整句未匹配直接当作字段全缺失的问题，但**尚未完成自由文本目标、条件、确认范围的可靠语义归并**。未启用新训练锚点，默认 v1 和现有实验保持不变。

## 实现边界

`tau3_grpo/algorithms/anchors/grounded.py` 提供 `extract(prefix)` 与 `validate(prefix, report)`：

- 文本字段含 `message_index/role/start/end/quote/message_sha256`。用户 ID、订单号、支付 ID、卡尾号、航班、日期、舱位、金额和条件标记来自可见原文；字段类型明确标记为 **mention（提及）**。
- 工具事实含调用/返回位置、`call_id`、JSON Pointer 和返回内容 hash；关联有序工具响应、检查查询对象一致性、区分错误和修改操作。只有已收到的返回能够作为事实，当前待生成动作和后续结果不能倒灌。
- 用户提及、助手陈述、工具观察分别保留。`user_id` 相同只表示值对应；数据库里的订单归属不等于对发言者完成身份认证。
- 卡尾号与返回支付方式对应；同一尾号命中两个支付对象时标记 `ambiguous`，不取第一个。匹配也不自动代表用户选择了该卡；否定或备选卡仍可能被提到。
- 保存所有助手金额陈述及其整段上下文，不把每个金额都解释为退款，不用工具价格覆盖报价。货币、正负号和千分位规范化有单独检查。
- 状态审阅视图包括完整用户上下文、工具支持的用户—订单关系、历次金额陈述、支付对应关系和简短确认/拒绝候选。`Yes` 的候选仅关联前一条助手消息，`approved_operation` 仍为空；它可能回答的是“是否查询”，不能自动当作修改授权。
- 未解释文本和旧承诺完整保留在 guard 中；抽出若干字段不等于可以删掉其余句子。`semantic_complete=false`、`training_eligible=false` 明确区分证据层与训练锚点。
- 校验器检查前缀、原文位置、角色、值、JSON 路径、调用关系、字段缺失和 guard 篡改。按规范化 JSON 比较，避免 Python 的 `True == 1` 将布尔/数值篡改误判为相等。

目前没有通用的“这段文字支持这个业务结论”的蕴含判断器。校验通过证明出处和有限抽取规则一致，**不证明目标完整、条件已解决、许可已成立或语义等价**。

## 真实状态需要保留什么

- **1035**：用户请求从 business 改为 economy，指定 GAST7Q；助手说明 $654 退款和 Mastercard 尾号 2734，用户随后回复 Yes。目标证据、订单/支付工具证据、完整报价与回复出处应分别保留，而不是仅从一个金额推出完整方案。
- **1060**：同一任务的轨迹曾出现 $2331 与 $272 两种退款陈述。即使最终工具状态或奖励相同，已向用户承诺的金额不同，不能合并。工具事实与对话承诺分栏正是为保留该区别。
- **1106**：同时修改航班日期和增加两件行李；还含“最佳 premium 服务”、免费行李条件、收费卡与退款原卡两个不同支付角色。提到卡 7447 不能直接消除原卡 1907 的退款承诺。
- **363（新留出）**：用户先想删除第二位旅客，随后改为全部旅客降舱，后续又确认不同航班及 $2910/$2888 两个方案。必须处理目标替换和重新确认；简单的最近一次 cabin/amount 不能解释全部状态。
- **548（新留出）**：取消后重新预订涉及两项操作、拒绝保险、原卡与备用卡，以及 7 位“尾号”。不能把尾号文本强行规范化为真实支付 ID。
- **895（新留出）**：先取消一个合资格订单，随后询问另一订单改时间并明确不升级。两个阶段、不同订单及否定条件必须分开；提到 business/economy 不等于新的改舱目标。

这些是上下文审阅结论，不作为自动训练标签。尚缺独立复核的完整状态标注与语义等价对。

## 使用与复现

配置开关为 `configs/analysis/grounded_evidence_20260914.yaml` 的 `enabled`，默认函数调用不启用；它仅控制离线审计，不改变 `TAU3_GRPO_ANCHOR_VERSION`。

在 `code` 目录及 `.venv-cpu` 中执行：

```bash
CUDA_VISIBLE_DEVICES='' PYTHONPATH=.:verl:tau2-bench/src TAU3_GRPO_TEXT_ONLY=1 \
.venv-cpu/bin/python -m tau3_grpo.analysis.audit_grounded \
  --config configs/analysis/grounded_evidence_20260914.yaml \
  --replay-dir results/analysis/grounded_evidence_20260914/holdout_replay \
  --output results/analysis/grounded_evidence_20260914/new_audit
```

输出目录必须为新路径，以避免覆盖旧证据。`decisions.jsonl` 保存原文引用、关联工具事实、状态审阅视图和完整报告 hash；大段工具结果不重复写入，完整报告可按固定源文件与前缀重建。

- [验证记录](grounded_evidence_verification_20260914.json)：开发/留出统计、源码与输入校验、抽取规则锁、13 项字面检查结果。
- [留出字段审阅证据](grounded_evidence_holdout_labels_20260914.json)：逐项原文位置、类型和值，可用 `python -m tau3_grpo.analysis.score_grounded_labels` 重新核验。
- `tests/fixtures/grounded_evidence_real_20260914.json`：3 个开发集真实完整前缀与手动选定字面字段预期；不是全量语义标注。
