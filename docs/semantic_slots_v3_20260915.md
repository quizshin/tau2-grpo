# 增量语义状态 v3：远程回归与边界

本轮接续磁盘整理前暂停的语义状态修复。主代码位于远程
`/root/autodl-fs/tau3-core/code`，使用对应持久环境进行 CPU 验证。
`airline_slots_v3` 是显式启用的离线候选，未接入在线 RL，未改变 v1/v2 默认行为。

## 问题与实现

旧增量回归通过 13/24 个位置，step1/3/6 分别为 8/8、5/8、0/8。
拒绝原因包括乘客范围、遗漏标识符证据和错误绑定确认问题。
这些错误既有表示能力限制，也有模型解释错误，不能全部靠放宽校验解决。

- **身份回答**：增加有严格语法边界的 `identity` 事件，只表达完整的 ID 回答。
  保存为用户声明，与工具核验事实分开；不建立 lookup 目标，不替换原目标，
  不代表操作批准。身份改变使已有批准失效；附带条件/请求的回答仍拒绝该类型。
- **乘客范围**：明确的 “all 3 passengers” 可表达全员；只有 “3 passengers”
  则为带原始前缀保护的数量选择器，不能推断全员或具体身份。费用乘法不能证明全员。
- **问题类型**：增加选择选项、探索选项和订单 ID 问题；这些问题不得绑定写操作批准。
  保留问题原文 hash，不能仅凭问到相同字段就丢掉其他条件。
- **金额**：区分交易收费/退款与票价表、原价、余额；支持受限 Markdown 金额标签。
  金额角色仍须有当前引用证据，不能从历史价格或工具计算补齐。
  v3 不强迫所有参考金额成为收费/退款字段，而把含金额的助手原文及金额列表完整
  放入 `financial_context` 并参与状态 key。改变任何参考价格仍会改变 key。
- **引用**：不自动补上模型遗漏的 ID 引用；提示词要求显式引用前文或已观察事实。
  新提示词同时区分候选选项与可执行报价，不把选择问题解释为批准。

这些是保守的有限规则，不是通用自然语言理解器。完整原文保护可能继续造成漏合并；
通过证据校验不等于状态语义完全正确，更不等于信用分配或训练收益已经得到证明。

## 远程验证

- 首轮相关测试 150 项通过；修复下述边界后 155 项通过，涵盖身份与目标/批准分离、乘客数量与全员区分、参考价格、
  交易角色、缺少证据、选项问题、增量不可变历史和缺失输出不可补造。
- 修改前冻结 153 个历史 fixture 编译结果（无 slot schema、v1、v2），修改后逐项完全一致。
  签名为 `9c85fa82d7b51cf9779a169de061596e2b3d0cd31670e2e4abe857d0ea95a923`。
- 新增 `tau3_grpo.analysis.replay_semantic_incremental` 原样重验保存的 delta，
  不调用模型、不修改事件、不推测缺失后继。源数据、代码和输出都有哈希记录。

误当成乘客范围限制；不能简单解释为模型人数判断错误。

### 运行结束后的边界修复（无新增请求）

在保持上述原始结果和运行源码快照不变后，另行修复：

1. 陈述“退回原支付方式”不等于“询问选择哪个支付方式”；明确的选择问题仍不能当批准。
2. 仅有一个金额值、角色标签明确的 Markdown 退款行可识别；旧/新两列都有金额的表格
   仍拒绝，不能猜取某列；原价行也不能变成退款。
3. 旧 `other/remove` 别名路径同样执行 v3 乘客范围检查，避免绕过限定词保护。

用保存的 delta 原样重验，两处误拦的增量已通过。但原调用链在这些位置中断，
后续事件没有生成；另有一次输出截断也没有可用 delta。因此完整位置统计仍为
17/24，不把缺失后继补造为成功，也没有再次调用模型。

当前主要剩余问题是：选择/搜索阶段与可执行方案的区分、方案替换引用、乘客姓名的
独立表示，以及复合问句/条件的作用范围。应进一步改进事件表示并做独立任务审计，
不继续靠放宽关键词规则提高通过率。当前样本终局奖励全部为 1，没有可变终局奖励组，
不能证明信用分配收益；这也不意味着考虑折扣和长度后的步级信号必然为零。

## 产物与复现

远程产物根目录：`results/analysis/semantic_v3_20260915/`。

- `baseline/`：冻结输入、旧请求输出和修改前历史状态签名。
- `tests-first.log`、`tests-final.log`、`historical_compatibility.json`：测试与旧行为一致性证据。
- `saved_deltas_airline_slots_v2/`、`saved_deltas_airline_slots_v3/`：零新增请求的重验结果。
- `fresh_source_manifest.json`：真实回归启动前冻结的代码、提示词、配置与数据哈希。
- `fresh_run_sources.tar.gz`：上述真实回归实际使用的源码快照，包含修复前边界。
- `api_v3_glm/`：真实请求 delta、状态和最终汇总；日志和退出状态在同级目录。
- `api_v3_boundary_replay/`：边界修复后的零新增请求重验，与原始真实回归分开保存。

只重验已有输出（无模型请求）：

```bash
source /root/autodl-fs/tau3-core/activate.sh
cd "$CODE_ROOT"
python -m tau3_grpo.analysis.replay_semantic_incremental \
  --config configs/analysis/semantic_incremental_v3_regression_20260915.yaml \
  --source results/analysis/semantic_v3_20260915/baseline/results/analysis/semantic_incremental_20260914/regression_glm \
  --output results/analysis/semantic_v3_20260915/replay_new_run
```

输出目录必须不存在；不得覆盖历史结果。新模型调用使用 `audit_semantic_api`，
会产生实际 API 费用，不因离线重验通过而自动启动 RL 或扩大请求预算。
