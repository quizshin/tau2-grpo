# MT reference_write/v3 固定 buffer 信用对照（2026-09-21）

已完成 CPU 离线对照：去掉后续过程奖励后，正优势错误轮从381降至68；成功轨迹中正奖励写入的正信号保留。但成功轨迹中242个无即时奖励轮失去正信号，同轮混合调用仍未解决。**可保留为时间信用候选，不直接替换正式算法，更不能据此宣称会提点。**

本次未启动GPU、采样或训练，未改奖励、生产算法、历史分数及任何旧buffer。使用实际训练过的reference_write/v3 DF off，未混入paper_env_split_v4。

## 固定设计与验证

在首次候选计算前写入 `results/analysis/mt_credit_comparison_20260921/spec.json`，SHA256 `f580a42f75f7c5e7508b0d23e3471bf811552accb449f6335a9b53d3a41215b3`。固定20份原始buffer、1,280条轨迹、50任务、160个原始8轨迹组、12,591轮，保持奖励、终局分数、gamma=0.9、lambda=0.3、eps=1e-6及mask不变。两个诊断分开运行，不叠加，也未搜索参数。

记r为当前轮奖励、F为折扣后的后续过程奖励、O为折扣至当前轮的终局结果；N为原UID/轮位置组的总体标准差归一化，E为原UID终局优势：

- 原算法：`A = N(r + F + O) + 0.3 E`。
- 时间对照T：`A_T = N(r + O) + 0.3 E`。均值和标准差全部重算，仍排除缺失轮；不是此前固定分母减掉贡献的归因统计。
- 同轮调用诊断D：原位置组有效时，`D_call = A + (r_call - r_turn)/(std_original + eps)`；无有效组方差时保留A。仅去掉自己同轮其他调用的即时奖励，固定原均值、分母及其他成分。这是事件敏感性诊断，不是完整调用级算法。

复用原生产奖励、优势和mask回放，baseline最大误差5.774e-15。另以Python statistics独立重算T，最大误差1.388e-11，小于预设1e-10容差；5项合成边界检查通过。每次update另给出按原生成token加权的RMS等尺度结果：正缩放系数1.0030–1.1779，不改变符号，原始/等尺度统计均留档。尺度匹配不能保证实际PPO梯度相同。

目标切片52→8实际为47轮正转非正，同时新增3轮正优势；不能写成“只修好了44轮且没有反作用”。32个有该切片的任务里8个减少、23个不变、1个增加：airline_479从2变5。剩余8轮全部含同轮正奖励调用，进一步显示时间和调用粒度是两个不同问题。

预先指定的保守筛查门槛通过：减少目标错误正信号，成功轨迹中干净正奖励写入及后续首次正奖励写入均无正转非正。但该门槛只用于诊断，未覆盖全部行为；“错误后首次正奖励写入”只是恢复代理，不保证是在修复同一错误。

必须同时看到以下风险：

- 成功轨迹整体有260轮正转非正：18轮有执行错误，**242轮无即时奖励**；260轮中257轮后续有正奖励写入。查询、推理和确认可能需要这些长程信用，不能将其全部认作应删除的噪声。
- 所有干净正奖励写入中仍有3轮丢失正信号，均来自官方失败；官方失败后的恢复代理也有1轮丢失。所有成功正奖励写入信号保留不等于所有正确动作信号保留。
- 官方失败中的正奖励写入正优势71→91。这仍可能强化“局部命中参考但终局错误”的行为；去掉F不会自动解决整体目标一致性。
- 原始轮位置组共1,945个，其中130个只有1条轨迹；零方差位置组260→474。原8轨迹分组没有变化，但后期有效位置支持不足更明显。逐位置支持1–8、全成功/全失败/混合组和50任务切片均保存。

两个定向案例：

- step9/line27/turn6（airline_1075），错误订票且没有自己的后续正过程奖励，原A=+1.670726，T=−0.707092：相对其他轨迹“后面没那么糟”的正贡献被消除。
- step12/line25/turn7（airline_981），错误订票和两个正确取消同轮，原A=+1.880022，T=+2.387607：时间对照反而放大混合轮的正信号。

## 同轮调用诊断：定位问题，但不能直接使用该公式

此处单位是**调用**，不是上表的轮。1,396次工具错误调用中，原正优势387次，去同轮其他即时奖励后382次：8次正转非正，3次非正转正。官方失败的错误调用为59→57，说明仅去掉同轮即时奖励并不能消除大部分长程相对正贡献。

airline_981上述混合轮中，错误订票的事件诊断从+1.880022变−0.414682；两个正确取消各仍为+1.076875，清楚定位到同轮信用混用。但全量1,056次正奖励调用里有118次正转非正，其中成功轨迹32次；某轮三个错误调用各去掉其他错误的惩罚后，又产生3个新正信号。因此**D不能直接当成训练公式**，需要独立设计调用层基线和长程信用的组合。

历史保存的是精确轮级token span，没有可认证的调用级token span。本次未重新分词伪造边界，也未声称完成调用级token更新。step2/line6/turn8的中性取消存在用户同意和24小时窗口，T保持原+0.782707；仍不能将非参考调用自动设为负奖。

## 决策与下一步

本次更支持先研究**局部信用与长程信用的作用范围**，不支持简单增加负奖或直接换成上述某个诊断公式。时间对照T保留为单因素候选；D仅保留为混合信用证据。正式算法保持原状。

若继续实现，先补真实生成时的调用token边界记录，并设计区分调用与非调用文本的信用组合；重点保护无即时奖励的前置行为。这一步应先做CPU边界和离线对照，再另列有界GPU实验。不要将时间变化、调用粒度和奖励改动同时打包后直接训练，也不自动重启20步实验。

以上数据已在开发审计中反复看过，并非盲测。优势符号不等同于动作概率变化；没有PPO比率、裁剪、KL和实际更新，不能证明这些机制导致既有MT分数下降，也没有新的pass@1。
