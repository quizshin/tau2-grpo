# 4B SFT 与 RL：双 A800 结果复核（2026-09-11）

按用户最新要求，本报告仅分析Qwen3.5-4B。通过SSH连到原051实例，当前无GPU；本次从持久盘原始记录重算统计，并执行CPU测试，没有新增训练或生成评估。服务器保持无卡开机。

**结论：4B LoRA SFT收敛正常，E0–E3均验证了真实RL更新；当前不能证明最终RL模型优于SFT，也不能把E2列为性能赢家。**

## 2. 4B E0–E3 RL

每组同一4B SFT起点，新建RL LoRA；GPU0策略训练与rollout，GPU1为27B INT4用户模拟器。每组仅6个任务×4轨迹，共3次更新。各组训练模型独立，不承接前一组权重。

| 方法 | 三批成功数 | 总成功率 | 第一次更新之后的两批 | 循环分钟 |
|---|---|---:|---|---:|
| E0 GRPO | 6、1、1 | 8/24，33.33% | 2/16 | 61.05 |
| E1 动态过滤 | 4、1、3 | 8/24，33.33% | 4/16 | 59.73 |
| E2 Tau-GiGPO | 8、1、2 | 11/24，45.83% | 3/16 | 59.57 |
| E3 两者结合 | 7、1、1 | 9/24，37.50% | 2/16 | 57.29 |

第一批是在任何RL更新之前生成，同一起点却分别成功6、4、8、7条。这说明并发模拟器与采样噪声已经带来明显差异。后两批又换了任务，不能把下降解释成训练退化；“更新后两批”也不是最终检查点的独立评估。第三步的最终权重没有被本轮第四批采样测试。

E2最高只能叫“这次训练轨迹成功数最高”。E2/E3与E0/E1的优势归一化也不同，不能进行新增step项的单变量因果归因。

### 更新信号

- E0 grad norm：0.311708 / 0.214437 / 0.140381。
- E1：0.293079 / 0.213152 / 0.211807；保留有效组2/1/2。
- E2：0.009775 / 0.134192 / 0.115353；三批均有已审计的独立GiGPO step贡献。首批全成功仍可因折扣后的剩余步数不同产生step信号。
- E3：0.137961 / 0.153496 / 0.181516；每批只保留1/2组，但均执行actor更新。

历史逐张量审计验证496个actor LoRA张量映射到640个vLLM缓冲区。此次另外读取并计算了四个最终adapter的SHA256，确认各自约123.92MiB文件可读、精确SFT基座路径存在。未重新加载GPU模型或重复逐张量同步审计。

E0/E1的平均 `pg_loss` 接近零不代表梯度为零：组内中心化优势会让标量平均接近零，而参数梯度仍可非零。本轮需要联合看grad norm、优势、实际参数与推理同步证据。

抽查 E1 第二批 airline_760，模型先称退款800美元，工具实际返回1253美元，随后才改口；还声称退款到账时间。E2同任务的一条轨迹无法完成票价查询，最后转人工。这说明流畅回复和调用工具不等于可靠完成任务，错误金额、工具规划与对话冗长仍值得关注。示例不构成所有失败的根因统计。

## 3. 两张卡是否用得合理

4B RL GPU0峰值约77.88–77.89GiB，GPU1约49.92–51.01GiB。各卡峰值相加约127.8–128.9GiB，占160GiB约80%；采样峰值不一定同时发生，不应当作实时总量。GPU0余量仅约2.1GiB，而GPU1仍有约29GiB余量。显存不能跨卡直接相加供单卡actor使用。

E1–E3每批actor更新约549–554秒；E3过滤掉一半任务组，更新耗时仍接近E1/E2，说明当前fixed-rollout过滤没有实测体现为actor计算节省。它已经支付全部rollout成本，主要作用是选择训练信号。不要为了“用满160G”直接加大GPU0 batch或上下文；本轮只证明当前短程负载能跑。

SFT allocated与RL整卡峰值是不同统计口径，不做直接倍数比较。

## 4. 本次无卡测试与尚缺验证

本次远程 CPU 回归 **131 passed，92.31秒，退出码0**，覆盖指标、评估运行逻辑、动态过滤、Tau-GiGPO、SFT数据、rollout边界、会话隔离和评分器。通过不等于排除所有潜在问题，也不替代真实GPU评估。日志：`results/analysis/a800_20260911/cpu-tests-remote.log`。

远程现有版本缺少本地新增 `test_eval_scoring.py` 等独立评测文件。本次首次指定该文件时pytest未收集任何测试，随后对远程确实存在的8个测试文件重新执行；不把第一次空运行计为通过。没有为了分析而覆盖远程训练源码。

远程没有发现新独立评估格式的 `evaluation/**/run.json`，4B SFT/E0–E3文档与记录也明确独立评估未执行。本次可完成离线统计与代码回归，无法在无卡模式下新增4B+27B真实生成对照。

下一步应先补齐并验证独立评测部署，再冻结4B SFT、E0、E1、E2、E3的最终模型，在同一selection集合、同一27B模拟器与采样预算下评测。标准预算60任务×4次×5模型=1200条，报告pass@1/@2/@4及pass^4、任务配对置信区间、失败类型和耗时。RL adapter必须合并到精确SFT基座，不能合并到原始4B基座。官方最终50题继续留到模型选定后。

不能用每组约60分钟的“训练+采样”循环直接估算纯评估用时；开GPU后先测同一冻结方案的吞吐。当前只保留推理权重，完整优化器状态已按此前授权精简，不能宣称支持原训练的精确断点续训。
