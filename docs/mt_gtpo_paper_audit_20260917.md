# MT-GRPO + GTPO + IRC：论文一致性审计与修复方案

日期：2026-09-17。此次仅核查原文、本地/远程代码与已完成训练记录，没有修改算法或启动训练。

原文：`../references/papers/26-arxiv-Multi-Turn Reinforcement Learning for Tool-Calling Agents with Iterative Reward Calibration.pdf`（相对于项目code目录）；arXiv:2604.02869v1，2026-04-03。重点核对§3.2 Eq.(2)、§4 Algorithm 1、Table 4、§4.3与Appendix A，相关PDF页面已渲染检查。

结论：当前v3是“论文Hybrid优势公式 + 自定义reference-write奖励”的工程变体，不是论文MT-GRPO + GTPO + IRC完整复现。当前结果不能当作对论文方法的否定。

## 一致与不一致

|项|论文原文|当前正式v3|判断|
|---|---|---|---|
|Hybrid优势|GN(逐轮折扣回报+折扣终局)+lambda GN(outcome)|G_K=outcome；G_k=r_k+gamma G_(k+1)；A_k=GN_(uid,k)(G_k)+lambda GN_uid(outcome)|主要公式一致|
|gamma、lambda|0.9、0.3|0.9、0.3|一致，不能当作实现误设|
|组内比较|同prompt、同turn position|同采样uid、同生成轮序号|符合原文方法；语义状态分组属于新改进|
|gold exact|匹配gold动作为1.0；没有本文v3的DB-write限定和总预算1规则|只有首次匹配参考DB写操作为1/M；总正奖励不超过1|改变了奖励定义与任务间尺度|
|soft match|Appendix A：0.5+0.5×参数重合比例|实际奖励0；只有candidate字段可能非零|不一致|
|state-change|IRC校准后非gold状态改变类别为-0.1|执行成功但非参考写入实际奖励0|不一致，存在额外写操作不受过程惩罚的缺口|
|duplicate|§4.1列出-0.2，最终各版本细节未完整公开|实际奖励0|与文中列出的规则不同；仍需确认作者最终版本|
|error / 普通read / message|错误-0.1；校准后普通read=0；message=0|对应实际奖励一致|这部分一致；gold/read重叠的优先级仍需明确|
|参数比较|排序字典列表、数字字符串转换、移除空值、递归比较|仅复用实际工具嵌套模型转换；顶层键/ID/列表顺序严格|不同，当前是环境执行等价变体|
|IRC闭环|采样→类别区分度→调权重→检查优势方向及回报/成功关联→迭代|存在重算/相关性/建议权重审计工具，但没有完整迭代、收敛判据及经校准配方的训练链路|核心流程未完成|
|动态过滤|不是这篇论文主要解决办法|可选按优势是否非零整组过滤，当前关闭|附加工程能力，无法验证奖励语义|

奖励代码里DEFAULT_WEIGHTS虽然有state_change=-0.1、duplicate=-0.2、soft_match=0.5，但v3实际支付分支只处理error与匹配参考DB写，其他全部0。不能根据权重字典认定相应奖励已进入训练。

代码定位：
- `tau3_grpo/algorithms/mt_gtpo.py:88`：折扣回报、同轮归一化、Hybrid组合。
- `tau3_grpo/evaluation/process_reward.py:209`：实际v3支付逻辑。
- `tau3_grpo/analysis/calibrate_process_rewards.py:93`：单次IRC统计；输出建议而非完整校准闭环。

本地与远程上述三个文件SHA256一致。本次核查的是当前代码以及存档run的v3启动参数，不把工作区文件等同于不可变的完整训练源码快照。

## 需要修正此前诊断的表述

1. gamma=0.9、lambda=0.3来自论文，不是随意添加的参数。实际数据可能需要重新校准，但不能把它们不适配的可能性说成“不按论文实现”。
2. 按轮序号分组属于论文方法。按语义状态分组是额外算法实验，不是论文复现修复。
3. 论文定义turn-level优势，没有充分描述多工具同轮的精细token归因。单工具调用归因可以后续研究，不能保证它是原论文要求。
4. 失败轨迹的正确动作获得正优势并不自动构成错误。论文也希望学习失败轨迹中的正确局部动作。要检查类别条件平均方向、真实错误动作的正向信号、最终DB一致性，不能要求失败轨迹所有token均为负。
5. 论文IRC是离线/人工分析迭代方法；在线自动调权EDG被列为未来工作。因此缺少每步自动改权重本身并非违反论文，缺少完整校准证据才是关键问题。
6. 图示中的read=0不能保证实际优势为0：Eq.(2)含未来奖励与终局项，零即时奖励也可能具有非零优势。不能从图示推导逐token零梯度保证。

## 当前训练数据给出的校准警告

从20个训练batch的1280条轨迹计算类别是否出现与二元终局成功的point-biserial相关（不含selection/final）：

|当前分类|相关系数rho|该类所在轮平均Hybrid优势|
|---|---:|---:|
|soft_match|-0.4082|-0.2012|
|error|-0.3781|-0.3971|
|state_change|-0.1308|-0.3398|
|duplicate|-0.0842|-0.1858|
|gold_exact|+0.0620|+0.2703|
|read_only|+0.0543|-0.0963|
|message|未定义|-0.0209|

当前soft分类不等于论文规范化后的soft分类；这些相关不是因果效应，不直接转成正式训练权重。特别是gold_exact含命中的参考查询，1273/1280条出现，只有7条不出现，区分度与支持不足；message全部出现因此相关未定义。现有工具的min_support=20会阻止对这类不充分子集直接建议权重。

这说明需要先统一分类语义再校准，不能只把soft从0改成论文的正数就开训。类别平均优势为负与部分错误调用所在轮优势为正可以同时成立，不能拿后者声称已违反论文“类别平均方向”指标。

## 修复实施顺序（尚未执行）

### 1. 建立可审计的论文配方，保留v3

新增独立paper模式，不改变历史reference_write v1/v2/v3含义。
按原文实现gold/soft/read/state/error/duplicate/message各层，移除该模式的1/M和总正预算1规则，匹配器与环境执行等价模式分开。
明确gold、soft、非gold写入和duplicate分类优先级；补全错误订单、部分参数匹配、嵌套类型、列表顺序、空值、合法重试与多工具调用的回归案例。
论文未给出的多调用聚合、缺失轮处理、std约定、IRC alpha/delta/eta、最终各版本权重等设为显式配置，记录假设，不宣称逐行复现作者代码。

### 2. 先在训练轨迹完成IRC校准

使用现有完整训练buffer启动校准；按训练任务划分校准与留出审计，禁止用selection60或final50拟合权重。
重新分类，统计各层成功/失败出现率、point-biserial、支持数，并单列DB写gold与参考读取gold用于诊断。
显式实现alpha/delta/eta、intended_sign、类别平均方向和回报-成功关联检查；同时重算正式训练实际使用的Hybrid优势，避免仅验证Algorithm 1中的代理项。
检查错误写入、错误调用与混合调用轮的信号，特别处理“取消目标之外订单仍拿满过程奖励”的回归案例。
每轮保存输入hash、规则版本、候选配方、优势重算与留出审计报告；需要时按新配方采集新训练buffer再迭代。
未知/零方差/支持不足不作为通过；校准失败应报告失败，不把“脚本能运行”当作IRC完成。

### 3. 冻结后做最小对照

保持与GiGPO一致的SFT起点、train50、任务调度、1280候选预算和评测协议；优先比较：
- 当前v3（已有结果）；
- 相同Hybrid、全部过程奖励0；
- 相同Hybrid、论文分类并经IRC校准的冻结奖励。

DF维持关闭以隔离主要差异。保留DF独立开关；不将动态过滤作为奖励语义修复。
归一化、gamma/lambda、学习率/KL若后续调整，单独立项以免混淆奖励效果；确认后再考虑跨seed复现。

### 4. 再研究论文以外的增强

如果校准后仍有错误调用共享正优势，单独研究call-level归因、对可验证DB破坏的惩罚或进度差分奖励。这些均为新增算法，不标成原论文复现。
不能简单把所有非参考写判为错误，也不能认为state-change=-0.1保证整轮优势一定为负；正负奖励聚合与组归一化仍需端到端验证。
